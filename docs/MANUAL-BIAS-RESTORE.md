# 기존 Bias 수동 복원과 다른 온도 조건에서의 재사용

## 목적

Low 대역의 Bias를 -30℃에서 한 번 찾고 -30℃, -10℃, +10℃ 순서로 촬영하는 운용을 지원한다. 작업을 중단한 뒤 이전 보정값을 알고 있다면 AgentUI에서 해당 값을 다시 적용하고, 작업할 온도 조건의 레시피를 실행할 수 있다.

수동 입력값은 자동 탐색 목표인 **8500이 아니라 `GSK_LSB` 레지스터 값**이다. 기존 AgentUI의 LSB 표시와 `bias.json`의 `GSK_LSB`는 16진수 표기이므로 입력도 같은 표기를 사용한다.

| 기존 기록 | 입력 예 | 실제 값 |
| --- | --- | --- |
| AgentUI에 `0x42` 표시 | `42` 또는 `0x42` | 10진수 66 |
| `bias.json`에 `"GSK_LSB": "10"` | `10` 또는 `0x10` | 10진수 16 |
| 자동 탐색 목표 `8500` | 이 입력란에 사용하지 않음 | 픽셀 목표 레벨 |

입력 가능한 범위는 `00`~`FF`다. 다른 카메라에서 얻은 값이 아닌, 선택한 카메라에서 기록한 이전 값을 사용한다.

## 작업 순서

1. AgentUI에서 대상 카메라의 시리얼 제어 영역을 연다.
2. **기존 Bias 수동 복원**에서 원래 보정한 대역 Low/Mid/High를 선택한다. -30℃에서 Low로 보정했다면 -10℃와 +10℃에서도 Low를 선택한다. 대역은 현재 챔버 온도와 별개의 설정이다.
3. 이전 `GSK_LSB` 값을 16진수로 입력하고 적용한다.
4. 수동 복원 완료와 LSB 읽기값 일치 상태를 확인한다.
5. Master에서 이어서 작업할 온도 조건의 레시피를 선택해 실행한다. 예를 들어 -10℃부터 작업하려면 -10℃ 조건의 레시피를 실행한다.
6. Master가 현재 적용값을 확인하고 해당 조건 폴더의 `bias.json` 저장을 확인한 뒤 촬영한다.

현재 레시피에 자동 Bias 탐색 스텝이 있으면 그 스텝은 계속 자동 탐색을 수행한다. 수동 복원을 사용해 다른 온도에서 이어 작업할 때는 해당 온도 조건의 촬영 레시피를 선택한다. 이 변경은 기존 레시피의 시작 스텝이나 저장 회차를 자동으로 바꾸지 않는다. 새 실행의 제품 번호·회차 폴더 정책도 기존 규칙을 따른다.

## 수동 적용이 확인하는 내용

수동 적용은 기존 자동 보정과 같은 고정 레지스터를 설정하고 입력한 GSK_LSB를 쓴다.

| 레지스터 | 적용 값 |
| --- | --- |
| CINT | Low `0x93`, Mid `0xA3`, High `0xD3` |
| TINT_MSB / TINT_LSB | `0x02` / `0x73` |
| GSK_MSB | `0x01` |
| GFID | `0xAE` |
| GSK_LSB | 입력값 |

각 쓰기의 응답과 `ReadBiasAsync`로 읽은 GSK_LSB 일치를 확인한 뒤 성공 상태를 만든다. 모든 레지스터를 독립적으로 다시 읽는 검증을 의미하지는 않는다. 다른 온도에서 이전 설정을 복원하는 기능이므로 픽셀 목표 8500을 다시 탐색하거나 8500±100 충족 여부를 수동 적용의 성공 조건으로 사용하지 않는다.

수동 적용 성공마다 새로운 적용 ID를 발급하고 자동 보정 결과와 수동 복원 결과를 구분한다. 입력칸을 편집하는 것만으로 카메라 값은 바뀌지 않는다. 적용 실패·취소·카메라 패널 재생성 시 이전 성공 상태를 그대로 재사용하지 않는다. 수동 적용은 카메라의 비휘발성 설정 저장 명령을 자동 실행하지 않는다.

## 레시피 연결과 실패 처리

Master는 생산 촬영 조건에 이번 실행의 Bias 증빙이 없으면 `biasUseCurrent` 요청으로 현재 적용값을 확인한다. AgentUI는 요청한 보정 대역, 현재 적용 ID, LSB 읽기값을 검사하고 현재 센서·제품·온도 조건의 최종 `bias.json`을 저장·읽기 확인한다. 이 요청은 자동 탐색을 수행하지 않는다.

따라서 -30℃에서 자동 보정한 Low 결과 또는 수동으로 복원한 Low 결과로 -10℃와 +10℃ 조건의 파일을 만들 수 있다. 각 온도 조건에 새 요청 ID와 파일 증빙을 만들며, 이전 조건 폴더의 파일이 있다는 이유만으로 통과하지 않는다. Hot·Cold·Room 생산 촬영 모두 필요한 Bias 확인이 끝나야 진행한다.

수동 입력 적용과 필수 파일 확인에는 각각 **최초 1회 + 추가 재시도 3회, 최대 4회** 정책을 적용한다. 작업자 취소는 추가 재시도를 중단한다. 중복 작업이 이미 진행 중이면 겹쳐 실행하지 않는다. 파일 저장·읽기 확인이 최종 실패하거나 대역·적용 상태가 맞지 않으면 NG로 레시피를 중단하고 이후 촬영·이동을 차단한다.

같은 숫자를 수동으로 다시 적용해도 적용 ID가 바뀐다. 저장 확인 도중 다른 적용이 시작되거나 카메라가 다시 연결되면 이전 요청의 증빙으로 계속 촬영하지 않는다. 수동 적용값을 사용할 때도 마지막 파일 경로와 내용 검증은 유지한다.

**Master와 AgentUI를 공유 Core·Protocols를 포함해 같은 버전으로 반영해야 한다.** 구형 AgentUI는 `biasUseCurrent`를 지원하지 않으므로 정상 재사용으로 처리하지 않는다.

## 로그와 현장 확인

AgentUI 로그는 `%LOCALAPPDATA%\HeatingCameraSystem\AgentUI\logs\agentui-*.ndjson`에 기록한다. 수동 적용의 대역·입력값·읽기값·적용 ID, 재시도 번호와 실패 원인, 레시피 채택 요청 ID, 최종 파일 경로를 함께 확인한다. 기존 재시도·NG 로그와 설정은 [BIAS-RETRY-NG.md](BIAS-RETRY-NG.md)를 참고한다.

| 확인 항목 | 기대 결과 |
| --- | --- |
| 정상 이전값 복원 | 올바른 대역의 고정값과 입력 GSK_LSB를 적용하고 읽기값 일치로 성공한다. |
| -10℃에서 Low 복원 후 촬영 | -30℃ Bias 탐색을 호출하지 않고 -10℃ 조건의 bias.json을 확인한 뒤 촬영한다. |
| -30 → -10 → +10 순차 촬영 | 처음 자동 탐색한 Low 결과를 확인해 각 조건 폴더에 저장한다. |
| 잘못된 입력 또는 대역 | 입력 오류는 카메라에 쓰지 않으며, 요청한 대역과 현재 적용 대역이 다르면 레시피를 진행하지 않는다. |
| 쓰기 응답·LSB 읽기 불일치 | 성공 상태를 만들지 않으며 최대 4회 후 실패를 표시한다. |
| 최종 저장 경로 장애 | 파일 확인을 최대 4회 시도하고 NG로 중단한다. |
| 같은 값 재적용·재연결 | 이전 적용 ID로 촬영을 통과하지 않으며 새 유효 상태를 확인해야 한다. |

실장비에서 수동 입력값의 원래 센서·대역과 읽기값을 확인한 뒤 위 시나리오를 검증한다. 이 문서는 소프트웨어의 적용 절차를 설명하며 실장비 검증 완료를 의미하지 않는다.
