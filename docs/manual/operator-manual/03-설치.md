# 3. 설치


## 3.1 사전 요구사항

| 항목 | 필수 | 비고 |
| --- | --- | --- |
| Windows 10/11 64-bit | 예 | Master(WPF)·Agent(OpenCvSharp) 모두 Windows |
| .NET 8 SDK | 빌드 PC | 저장소에서 Master·Agent 게시 |
| Windows Desktop Runtime 8 | Master PC | `Microsoft.WindowsDesktop.App 8.x` 필요 |
| .NET Runtime 8 | Agent PC | `Microsoft.NETCore.App 8.x` 필요 |
| NATS 서버 | 예 | Docker 권장 |
| PLC(LS XGT FEnet) | 시뮬 시 불필요 | XGT 전용 TCP, 기본 포트 2004 |
| 카메라 + USB 가상 시리얼 | 시뮬 시 불필요 | 웹캠으로도 검증 가능 |


## 3.2 방화벽

| 포트 | 방향 | 용도 | 대상 PC |
| --- | --- | --- | --- |
| 4222/tcp | 아웃바운드 | NATS 클라이언트 | Master, Agent |
| 4222/tcp | 인바운드 | NATS 수신 | NATS 호스트 |
| 8222/tcp | 인바운드 | NATS 모니터링(선택) | NATS 호스트 |
| 2004/tcp | 아웃바운드 | LS XGT FEnet | Master |


## 3.3 NATS 서버

다음 명령은 저장소 루트에서 실행한다.

```
docker compose -f docs/deployment/docker-compose.yml up -d
docker ps | Select-String nats
Test-NetConnection -ComputerName 127.0.0.1 -Port 4222 | Select TcpTestSucceeded
```

원격 PC에서는 `127.0.0.1` 대신 실제 NATS 호스트 주소로 4222 포트 연결을 검사한다. Compose는 4222·8222 포트를 매핑하고 `restart: unless-stopped`를 사용하지만, 현재 구성에는 NATS 모니터링 활성화 옵션이 없으므로 8222 포트만으로 모니터링 화면이 제공되지는 않는다.

> 📷 **[그림 2] NATS 서버 기동 확인**
> - **캡처 대상:** docker ps 또는 NATS 콘솔에서 서버가 떠 있는 상태
> - **화면/상태:** NATS 컨테이너/프로세스가 실행 중인 화면


## 3.4 Master 설치

다음 명령은 저장소 루트에서 실행한다.

```
dotnet publish HeatingCameraSystem.Master\HeatingCameraSystem.Master.csproj -c Release -o publish\Master
# publish\Master 폴더를 운영 PC로 복사 후 HeatingCameraSystem.Master.exe 실행
```

최초 실행 시 %LOCALAPPDATA%\HeatingCameraSystem\ 에 hardware.json(기본값)과 data.db(빈 LiteDB)가 생성된다. hardware.json의 `Plc.IpAddress`, `Plc.Port`, `Nats.Url`, `Serial.PortName`을 실제 환경에 맞게 수정한 후 Master를 재시작한다.

> 📷 **[그림 3] hardware.json 생성 위치**
> - **캡처 대상:** %LOCALAPPDATA%\HeatingCameraSystem\ 폴더에 hardware.json·data.db가 생성된 탐색기 화면
> - **화면/상태:** 탐색기 주소창에 경로가 보이도록


## 3.5 Agent 설치

다음 명령은 저장소 루트에서 실행한다.

```
dotnet publish HeatingCameraSystem.Agent\HeatingCameraSystem.Agent.csproj -c Release -o publish\Agent
# 단일 인스턴스: HeatingCameraSystem.Agent.exe 실행 후 agent.json 편집 및 재실행
# 다중 인스턴스(CLI): HeatingCameraSystem.Agent.exe <AgentId> <NatsUrl> [CameraIndex] [StoragePath] [SimulationMode] [LogPath]
```

`agent.json`은 Agent 실행 폴더에 생성된다. `AgentId`, `CameraIndex`, `NatsUrl`, `StoragePath`, `SimulationMode`를 확인하고 수정한 후 Agent를 재실행한다. `SimulationMode`에는 JSON boolean인 `true` 또는 `false`를 사용한다.

> **[참고]** CLI 인수는 기존 `agent.json` 설정 중 제공된 값만 덮어쓴다. 여러 인스턴스를 동시에 실행할 때는 인스턴스별 Agent ID와 저장 경로를 분리한다.


## 3.6 카메라·시리얼 셔터 확인

- USB 비디오 장치 → 장치관리자 '이미징 장치'에서 장치를 확인한 후 실제 Agent 로그·미리보기·시험 캡처로 `CameraIndex` 확인 → agent.json CameraIndex
- 가상 시리얼 포트(셔터) → 장치관리자 '포트(COM & LPT)'에서 COM 번호 확인
- 셔터 → 문자열 명령이 아닌 7바이트 raw binary 프로토콜을 사용하므로 Master의 셔터 기능으로 동작 확인

> 📷 **[그림 4] 장치관리자 카메라·COM 확인**
> - **캡처 대상:** 장치관리자에서 이미징 장치와 포트(COM & LPT)가 함께 보이는 화면
> - **화면/상태:** 카메라·COM 포트가 인식된 상태
