# 2. 시스템 아키텍처


## 2.1 구성

| 구성요소 | 타겟 | 배포 RID | 역할 |
| --- | --- | --- | --- |
| Core | .NET 8 | — | 인터페이스·모델·설정. 외부 의존성 없음 |
| Protocols | .NET 8 | — | XGT FEnet(VagabondK)·NATS.Net·시리얼·카메라 구현체, Fake 포함 |
| Master | .NET 8-windows | — | WPF 운영자 UI, AppServices 정적 서비스 로케이터 |
| Agent | .NET 8 | — | 카메라 PC 콘솔 앱(OpenCvSharp + NATS) |
| AgentUI | .NET 8-windows | — | 카메라 런타임 WPF UI |
| AgentManager | .NET 8 | win-x64 | USB 카메라 자동발견 + Agent 승인·감독(로그온 예약작업) |
| Simulator / E2EDriver / ManagerE2EDriver | .NET 8 | — | 외부 시뮬레이터·E2E 드라이버 |

이 문서에서 `Manager`는 별도 구성요소가 아니라 `AgentManager`의 약칭이다.

```text
PLC ←─ XGT FEnet TCP 2004 ─→ Master ←─→ NATS ←─→ AgentUI
                                      ↑          ├─→ 카메라
                                      │          └─→ 시리얼 장치
                                      ├─→ Agent
                                      └─→ AgentManager
```

AgentManager 방식에서는 카메라 PC의 하나의 AgentUI가 같은 PC에 연결된 여러 카메라를 소유한다. AgentManager는 카메라마다 Agent 프로세스를 실행하지 않으며, NATS의 `runtimeLoad`·`runtimeUnload` 카메라 제어 명령과 `agent.status.*` 하트비트로 각 카메라 런타임을 감독한다.

> 📷 **[그림 1] 네트워크·설비 구성도**
> - **캡처 대상:** Master/NATS/Agent PC·PLC·챔버의 실제 네트워크 및 설비 배치도
> - **화면/상태:** 설비 문서의 구성도 또는 현장 배치 사진


## 2.2 NATS 토픽

다음 표는 운영 흐름의 핵심 8개 토픽이다. 예시는 `AgentId=PC01_a1b2c3d4`, `PCId=PC01`인 경우이다.

| 토픽 | 실제 예시 | 방향 | 동작 방식 | 내용 |
| --- | --- | --- | --- | --- |
| master.cmd.capture.{AgentId} | master.cmd.capture.PC01_a1b2c3d4 | Master→Agent/AgentUI | 명령 | 특정 카메라 캡처 명령 |
| master.cmd.capture.all | master.cmd.capture.all | Master→전체 | 브로드캐스트 명령 | 전체 캡처 명령 |
| master.cmd.camera.{AgentId} | master.cmd.camera.PC01_a1b2c3d4 | Master/AgentManager→Agent/AgentUI | 명령 | 카메라 제어(RUN/STOP/셔터/캡처/NUC, runtimeLoad/runtimeUnload 등) |
| master.config.serial.{AgentId} | master.config.serial.PC01_a1b2c3d4 | Master/AgentManager→Agent/AgentUI | 설정 명령 | 시리얼 설정 전송 |
| agent.result.capture.{AgentId} | agent.result.capture.PC01_a1b2c3d4 | Agent/AgentUI→Master | 결과 이벤트 | 캡처 결과(`IsSuccess`, Agent 측 `ImagePath`, `ImageBytes`) |
| agent.status.{AgentId} | agent.status.PC01_a1b2c3d4 | Agent/AgentUI→Master/AgentManager | 주기 발행 | 하트비트. 기본 주기는 설정값 5초 |
| agent-mgr.inventory.{PCId} | agent-mgr.inventory.PC01 | AgentManager→Master | 상태 이벤트 | 카메라 목록·승인·실행 상태 |
| server.cmd.mgr.{PCId} | server.cmd.mgr.PC01 | Master→AgentManager | 명령 | 승인/거부/이름/시리얼/재시작/비활성 |

그 밖의 설정, 응답, 실시간 영상 및 로그 토픽은 다음과 같다.

| 토픽 | 실제 예시 | 방향 | 동작 방식 | 내용 |
| --- | --- | --- | --- | --- |
| agent.live.{AgentId} | agent.live.PC01_a1b2c3d4 | Agent/AgentUI→Master | 주기 발행 | 실시간 프레임 이미지와 크기 |
| master.config.agent.get.{AgentId} | master.config.agent.get.PC01_a1b2c3d4 | Master→Agent/AgentUI | 요청 | Agent 설정 조회 |
| agent.config.agent.snapshot.{AgentId} | agent.config.agent.snapshot.PC01_a1b2c3d4 | Agent/AgentUI→Master | 응답 | 현재 Agent 설정 스냅샷 |
| master.config.agent.set.{AgentId} | master.config.agent.set.PC01_a1b2c3d4 | Master→Agent/AgentUI | 설정 명령 | Agent 설정 적용 |
| agent.config.agent.ack.{AgentId} | agent.config.agent.ack.PC01_a1b2c3d4 | Agent/AgentUI→Master | 응답 | Agent 설정 적용 결과 |
| agent.config.serial.ack.{AgentId} | agent.config.serial.ack.PC01_a1b2c3d4 | Agent/AgentUI→Master | 응답 | 시리얼 설정 적용 결과 |
| agent.ack.camera.{AgentId} | agent.ack.camera.PC01_a1b2c3d4 | Agent/AgentUI→Master/AgentManager | 응답 | 카메라 제어 결과 |
| agent-mgr.log.alert.{PCId} | agent-mgr.log.alert.PC01 | AgentManager→Master | 이벤트 | 경고·오류·치명 로그 알림 |
| server.req.log.{PCId} | server.req.log.PC01 | Master→AgentManager | 요청 | Agent 로그 덤프 요청 |
| agent-mgr.log.dump.{PCId} | agent-mgr.log.dump.PC01 | AgentManager→Master | 응답 | 압축된 로그 덤프 |

`agent.result.capture.*`의 `ImagePath`는 Agent 또는 AgentUI가 이미지를 저장한 카메라 PC의 경로이다. Master는 함께 수신한 `ImageBytes`를 Master PC의 로컬 캐시에 다시 저장할 수 있으므로, Agent 측 원본 경로와 Master 측 캐시 경로를 같은 경로로 해석하지 않는다.

AgentId 형식은 실행 방식에 따라 다르다.

- 수동 방식: `Agent_{CameraIndex}`
- AgentManager 방식: `{PCId}_{SHA256(HardwareId)의 앞 8자리 소문자 16진수}`

레시피 스텝에서 `CameraAlias`를 사용하면 Alias를 DB에서 조회해 AgentId로 변환한다. 조회가 실패하거나 저장된 AgentId가 없으면 `Agent_{CameraIndex}`로 대체한다.
