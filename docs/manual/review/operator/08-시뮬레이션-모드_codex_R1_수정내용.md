# 08-시뮬레이션-모드 — codex 검토 (Round 1)

## 종합 평가
- 수정 필요도: 상
- 한 줄 요약: 시나리오 구분표는 유용하지만, 실제 설정·실행·복구 절차와 주의사항이 없어 관리자가 이 장만으로 시뮬레이션 모드를 운용하기 어렵다.

## 수정 필요 항목
1. [시나리오 표 전체] 문제: `hardware.json SimulationMode=false`, `hardware.json + agent.json 모두 true`처럼 파일명과 필드 표현 방식이 일관되지 않고, 어느 객체의 어떤 필드를 바꾸는지 불명확하다. -> 제안: 각 파일별로 정확한 필드 경로와 값을 코드 형식으로 표기한다.
2. [운영(실HW)] 문제: `실제 PLC/셔터/카메라`라고 되어 있으나 `hardware.json` 설정만 제시되어 있어 카메라 Agent의 `agent.json` 설정이 누락되었다. -> 제안: 운영 모드에 필요한 `hardware.json`과 `agent.json` 값을 모두 명시한다.
3. [전체 시뮬] 문제: “모두 true”가 두 파일의 어떤 항목을 뜻하는지 알 수 없다. -> 제안: 파일별 설정 항목을 각각 적고, 시뮬레이션되는 대상이 PLC·셔터·카메라 중 무엇인지 설명한다.
4. [외부 Simulator] 문제: `Master real`은 한글 운영 설명으로 의미가 불분명하며, Master가 실제 PLC에 연결되는지 Simulator에 연결되는지 판단할 수 없다. -> 제안: “Master의 내부 시뮬레이션 비활성화 후 PLC 접속 주소를 외부 Simulator로 지정”처럼 필요한 연결 관계와 설정을 구체적으로 기술한다.
5. [하이브리드] 문제: `hardware.json true`는 필드명이 생략되었고 `agent.json false(웹캠)`도 웹캠 사용과 해당 값의 관계가 설명되지 않았다. -> 제안: 정확한 필드명과 함께 “PLC·셔터는 시뮬레이션, 카메라는 실제 웹캠 사용”처럼 동작 범위를 명시한다.
6. [E2E 명령] 문제: 명령을 어느 디렉터리에서 어떤 셸로 실행해야 하는지 설명이 없다. -> 제안: “저장소 루트에서 PowerShell로 실행” 등 실행 위치와 환경을 명시한다.
7. [E2E 명령] 문제: 세 스크립트의 선행 조건, 검증 범위, 성공 판정 기준이 없다. 특히 `run-manager-e2e.ps1`은 시뮬레이션 모드와의 관계가 드러나지 않는다. -> 제안: 각 스크립트별 필수 프로세스·설정, 자동 실행 여부, 검증 대상과 정상 종료 조건을 간단히 덧붙인다.
8. [장 전체] 문제: 설정 변경 후 적용 방법과 운영 모드 복귀 절차가 없다. -> 제안: 관련 프로세스를 종료한 뒤 설정을 변경하고 재시작해야 하는지 명시하며, 시험 종료 후 운영값으로 복원하는 절차를 추가한다.
9. [장 전체] 문제: 시뮬레이션 상태를 실제 장비 운전으로 오인할 위험에 대한 경고가 없다. -> 제안: 시험 전 실제 장비 연결 상태를 확인하고, 시험 후 `SimulationMode` 및 접속 주소를 운영값으로 복구하도록 경고문을 추가한다.

## 누락/추가 제안
- `hardware.json`과 `agent.json`의 실제 저장 위치를 안내한다.
- 설정 파일이 없을 때 생성되는 시점과 설정 변경 후 재시작 필요 여부를 명시한다.
- 시나리오별로 PLC, 셔터, 카메라, NATS, Simulator의 실제/모의 여부를 나눈 표를 제공한다.
- 외부 Simulator의 실행 순서와 종료 순서를 추가한다.
- E2E 실패 시 확인할 최소 항목으로 설정값, NATS 연결, Simulator 실행 여부, 콘솔 오류 위치를 안내한다.
- 명령 예시에는 PowerShell 프롬프트 표기를 사용하고, 경로 기준을 통일한다.
