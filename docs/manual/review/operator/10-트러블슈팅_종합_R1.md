# 10-트러블슈팅 — 검토 종합 (Round 1)

## 판정

수정 필요(다수 합의). 증상 목록은 적절하지만 실제 점검 순서, 정상 기준, 경로와 후속 조치가 부족하며 일부 내용은 현재 구현과 불일치한다.

## 합의·다수 수정 (코드 확인됨)

- 표를 `증상 | 원인 | 확인/조치`로 분리하고 통신 → 설정 → 장치 점유 → 로그 순서와 이관 조건을 명시한다.
- Agent 상태는 5초 하트비트와 Master의 15초 오프라인 판정에 근거한다. NATS 4222 연결 검사와 정상 기준을 추가한다.
- `Connected to NATS`는 실제 Agent 콘솔 출력이므로 유지할 수 있다.
- `hardware.json`, `data.db`, `agent.json`, Manager 상태·로그의 전체 경로나 관련 장 링크를 제공한다.
- 온도와 습도 PLC 값 모두 코드에서 10으로 나누므로 “온도는 ÷10”을 “온도·습도는 ÷10”으로 수정한다.
- `frame.Empty()`, `_openBuffer`, `_closeBuffer` 같은 내부 식별자는 운영자용 표현으로 교체한다. 빈 프레임은 로그 문구가 아니라 캡처 실패(`false`)로 처리된다.
- 셔터 상태 조회는 물리 상태가 아닌 소프트웨어 캐시이므로 COM 포트, 점유, 통신 설정과 실제 셔터 상태를 함께 확인하도록 안내한다.
- 챔버 안정화 완료 조건은 현재 코드상 목표 온도와 `TemperatureTolerance`뿐이다. 수동 중지 주체와 설정 위치를 명시한다.
- DB 장애는 모든 Master 프로세스를 종료한 뒤 재실행하고, 실패 시 원본 파일을 보존·백업하여 담당자에게 전달하도록 한다.
- 설정 변경 전 백업, 자동 운전 중지와 하드웨어 안전 상태 확인, 장애 시각·Agent ID·레시피 단계·오류 화면 수집 절차를 추가한다.

## AI 지적이 부정확 (코드검증)

- Codex의 “÷10은 온도값에만 적용” 제안은 부정확하다. `PlcXgtClient`는 현재 온도·목표 온도뿐 아니라 현재 습도·목표 습도에도 ÷10 스케일을 적용한다.
- AGY의 “목표 온도/습도 도달 실패 시 안정화 대기”는 부정확하다. `RecipeEngine`의 안정화 대기는 온도만 판정한다.
- AGY의 “`SimulationMode=true`이면 Manager가 Agent를 spawn하지 않음”은 구버전 설명이다. Manager 설정은 `SimulateEnumeration`과 `SimulateAgentMode`로 분리되었고, 현 Supervisor는 카메라마다 `Agent.exe`를 실행하지 않는다.
- “`*.db-log`가 있으면 자동 복구”는 애플리케이션 코드로 보장되지 않는다. 확정적 복구 절차로 안내하면 안 된다.
- `AgentExePath`의 기본 대상은 `Agent.exe`가 아니라 `HeatingCameraSystem.Agent.exe`이며, 현재 Manager 구조에서는 해당 점검 자체를 재검토해야 한다.
