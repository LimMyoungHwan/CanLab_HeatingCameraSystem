# 10-트러블슈팅 — 검토 종합 (Round 1)

## 판정

- Codex: 수정 필요도 **상**
- Claude: 수정 필요도 **중**
- AGY: 수정 필요도 **중**
- Kimi: 수정 필요도 **상**
- 리뷰는 절차화, 경로 명시, 내부 식별자 제거, 로그 수집 필요성에서 **수렴**했다. PLC 스케일, 챔버 안정화 조건, AgentManager 실행 구조, DB 복구 방법에서는 **충돌**하며 일부 지적은 현재 코드와 맞지 않는다.

## 합의·다수 수정 (코드 확인됨)

- [전체 구조] 단일 표만으로 점검 순서와 정상 기준이 부족함 -> `통신 → 설정 → 장치 점유 → 로그` 순서와 확인/조치·이관 조건을 명시한다. (Codex, Claude, AGY, Kimi)
- [표 구성] 원인과 조치가 `점검` 열에 혼재함 -> `증상 | 원인 | 확인/조치`로 분리하고 질문형 표현을 명령형으로 통일한다. (Codex, Claude, Kimi)
- [Agent 초록 점 안 뜸] 상태 판정 기준이 불명확함 -> Agent의 기본 하트비트 주기 5초와 Master의 15초 오프라인 판정, NATS URL·4222 포트 확인 절차를 명시한다. (Codex, AGY)
- [Agent 연결 확인] 실제 확인 문구가 없음 -> Agent가 NATS 연결 후 출력하는 `Connected to NATS`를 정상 기준으로 사용한다. (Codex, AGY)
- [캡처 타임아웃] `CameraIndex ↔ AgentId` 설명이 불완전함 -> `CameraAlias`로 등록 Agent를 우선 조회하고, 없으면 `Agent_{CameraIndex}`를 사용하는 현재 매핑 규칙과 `agent.json` 위치를 안내한다. (Codex)
- [캡처 실패] `frame.Empty()`는 운영자가 볼 수 있는 로그 문구가 아님 -> 드라이버, USB 연결, 장치 점유를 확인하고 Agent의 `Step …: FAIL` 로그를 확인하도록 바꾼다. (Codex, Kimi)
- [PLC 온습도 0 고정] 설정 위치와 연결 정상 기준이 부족함 -> `%LOCALAPPDATA%\HeatingCameraSystem\hardware.json`의 `Plc.IpAddress`·`Port` 및 `Test-NetConnection <PLC IP> -Port 2004`의 `TcpTestSucceeded : True`를 명시한다. (Codex, Claude, AGY)
- [값이 이상한 숫자] 스케일과 주소 확인 범위가 모호함 -> 현재 온도·목표 온도·현재 습도·목표 습도는 모두 raw word를 10으로 나누며, D/M/P 주소와 `UseHexBitIndex`는 실제 PLC 명세와 대조하도록 안내한다. (Codex, AGY, Kimi)
- [셔터 미응답] 내부 변수명 `_openBuffer`·`_closeBuffer`가 노출됨 -> COM 포트, 9600 8N1 등 통신 설정과 포트 점유를 먼저 확인하고, 기술 점검에는 ASCII가 아닌 7바이트 raw binary 프로토콜임을 별도로 명시한다. (Codex, Claude, AGY, Kimi)
- [셔터 상태] 화면 상태를 물리 상태로 오인할 수 있음 -> `GetShutterStateAsync`는 마지막 명령을 저장한 `_isOpen` 캐시를 반환하므로 실제 셔터 상태와 함께 확인하도록 안내한다. (AGY)
- [챔버 안정화] 완료 조건과 중지 주체가 불명확함 -> 현재 구현은 목표 온도와 `RecipeEngine.TemperatureTolerance`만 비교하며, 대기 해제 시간 조건은 없다. 중단은 운전자가 `STOP`으로 수행한다고 명시한다. (Codex, Claude, Kimi)
- [data.db 열 수 없음] 자동 복구를 단정함 -> 모든 Master 프로세스를 종료한 뒤 재실행하고, 계속 실패하면 `%LOCALAPPDATA%\HeatingCameraSystem\data.db`를 삭제·변경하지 말고 복사본을 백업하여 담당자에게 전달한다. (Codex, Claude, AGY, Kimi)
- [경로·보고] 상대경로와 장애 보고 정보가 부족함 -> `hardware.json`, `data.db`, `agent.json`, Manager 상태·로그 경로를 설치 기준 경로로 표시하고 장애 시각, Agent ID, 레시피 단계, 오류 화면을 수집하도록 한다. (Codex, Claude, AGY, Kimi)

## AI 지적이 부정확 (코드검증)

- Codex의 “÷10은 온도값에만 적용” 제안은 부정확하다. `PlcXgtClient`는 온도와 습도 모두 ×10/÷10 스케일을 적용한다.
- AGY의 “목표 온도·습도 도달 실패 시 챔버 안정화 대기”는 부정확하다. 현재 `RecipeEngine`의 안정화 완료 판정에는 온도만 포함된다.
- Kimi가 제안한 `TemperatureTolerance` 기본값 ±1.0°C와 60초 유지 조건은 존재하지 않는다. 현재 기본값은 0.5°C이며 허용 범위 진입 즉시 다음 단계로 진행한다.
- `frame.Empty()` 또는 `Frame is empty`는 Agent 콘솔에 출력되지 않는다. 빈 프레임은 캡처 실패로 반환되어 `Step …: FAIL`로 기록된다.
- “`*.db-log`가 있으면 자동 복구”, “정상 종료로 복구 유도”, “DB 재생성”은 애플리케이션 코드가 보장하는 복구 절차가 아니다.
- AGY의 셔터 전원 reset 제안은 코드나 프로토콜에 정의된 복구 절차가 아니다.
- `SimulationMode이면 spawn하지 않는다`는 과거 Manager 구조 설명이다. 현재 설정은 `SimulateEnumeration`과 `SimulateAgentMode`로 분리되었고, Manager는 카메라마다 `Agent.exe`를 실행하지 않으며 NATS로 AgentUI에 load/unload를 요청한다.
- `AgentExePath`의 기본 대상은 `Agent.exe`가 아니라 `HeatingCameraSystem.Agent.exe`이며, 현재 Supervisor 진단의 핵심 항목도 아니다.
- Manager 상태 파일은 `<InstallRoot>\Manager\manager-state.json`, Agent별 감시 로그는 `<InstallRoot>\logs\{AgentId}`이다. `%LOCALAPPDATA%\HeatingCameraSystem\logs`는 현재 Master 로그 경로로 구현되어 있지 않다.
- 레시피는 `data.db`에 저장되지 않는다. 현재 `FileRecipeRepository`가 `%LOCALAPPDATA%\HeatingCameraSystem\recipe` 아래의 개별 JSON 파일로 저장한다.

## 보류 (설비 안전/도메인 확인 필요)

- 자동 운전 중지 이후 히터·서보·셔터를 어떤 상태로 두고 전원을 어디까지 차단할지에 대한 현장 안전 절차.
- PLC D/M/P 주소와 `UseHexBitIndex` 변경 권한, 실제 XGB 설비 명세 대조 및 승인 절차.
- 셔터 물리 상태 불일치 시 전원 재설정·재연결 허용 여부와 복구 순서.
- 장애 심각도, 운영 중단 기준, 유지보수 담당자 이관 및 연락 체계.
- 시리얼 모니터 사용 가능 여부와 운전 설비에서 raw binary 송신을 검증하는 승인 절차.
