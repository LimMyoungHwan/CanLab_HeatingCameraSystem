## 합의·다수 수정 (코드 확인됨)

- [`hardware.json` 행] “Master 설정”만으로 범위가 불명확함 -> PLC, NATS, 시리얼 셔터, 흑체, 카메라 페어링, 보존 기간 등을 포함하는 Master 하드웨어·통신 설정으로 명시한다. 파일이 없거나 읽기 실패 시 기본값으로 다시 작성되며, 시작 시 한 번 읽으므로 직접 변경 후 Master 재시작이 필요하다. (Codex, agy)
- [`data.db` 행] 저장 내용이 불명확함 -> 대시보드 레이아웃, 촬영 이력, 챔버 이력, 알람 이력, 카메라 장치·시리얼 설정을 저장하는 LiteDB로 구체화한다. 레시피의 현재 저장소는 아님을 명시한다. (Codex, Kimi)
- [`recipe\*.json` 행] `data.db`와 역할 구분이 부족함 -> 현재 레시피는 `%LOCALAPPDATA%\HeatingCameraSystem\recipe\<RecipeId>.json`에 저장되며, 수정·삭제 전 버전은 `recipe bak`에 복사된다고 명시한다. (Codex, Kimi)
- [`agent.json` 행] 주요 설정과 생성 조건이 부족함 -> `AgentId`, `CameraIndex`, `NatsUrl`, `StoragePath`, 하트비트 간격, 시뮬레이션·로그 경로 등을 포함한다고 명시한다. 인수 없는 일반 실행에서만 누락 시 생성되고, CLI 인수가 있으면 파일 없이 기본값과 인수를 사용한다. (Codex, agy)
- [카메라 대상 매핑 설명] `Agent_{CameraIndex}`를 유일한 규칙처럼 안내하면 부정확함 -> 레시피 실행은 `CameraAlias`로 등록 장치의 `AgentId`를 먼저 찾고, 찾지 못할 때만 `Agent_{CameraIndex}`로 대체한다고 명시한다. (Codex)
- [캡처 이미지 행] 설정 키와 실제 경로가 혼재됨 -> 콘솔 Agent 원본은 기본 `<Agent exe>\ImageStorage\`이며 `StoragePath`로 변경할 수 있고, Master 수신 캐시는 `%LOCALAPPDATA%\HeatingCameraSystem\ImageCache\`임을 별도 행으로 유지한다. (Codex, Kimi)
- [`manager-settings.json`/`manager-state.json` 행] 두 파일의 역할과 생성 동작을 구분해야 함 -> 둘 다 `<InstallRoot>\Manager\` 아래지만, 전자는 시작 시 읽는 설정 파일이고 누락 시 기본값을 메모리에서 사용할 뿐 자동 저장하지 않는다. 후자는 카메라 승인·상태 변경 시 `ManagerStateStore`가 생성·갱신한다. (Codex, Claude, Kimi)
- [Agent 로그 행] 하나의 고정 경로로 단정함 -> 콘솔 Agent 기본 로그는 `<Agent exe>\logs\agent-YYYYMMDD.log`이고 `LogPath`로 변경 가능하다. AgentManager가 감시하는 경로는 `<InstallRoot>\logs\{AgentId}\`이므로 배포 시 Agent의 `LogPath`와 맞춰야 한다. (Claude, Kimi)
- [Agent 로그 형식·보관] “NDJSON, 7일 보관”이 부정확함 -> 콘솔 Agent는 한 줄 JSON 형식의 `.log` 일별 롤링 파일을 쓰고 최근 7개 파일을 보존한다. 날짜 기준 7일 삭제로 표현하지 않는다. AgentUI는 별도로 `AgentUI\logs\agentui-*.ndjson`을 쓰며 14개 파일을 보존한다. (Codex, Kimi)
- [누락 파일] AgentUI 런타임 파일이 빠짐 -> `%LOCALAPPDATA%\HeatingCameraSystem\AgentUI\agentui.json`, 기본 캡처 폴더 `Captures`, 로그 폴더 `logs`를 추가한다. `agentui.json`은 누락·읽기 실패 시 생성되고 저장 변경은 다음 실행부터 적용된다. (Kimi)
- [경로 표기] `%LOCALAPPDATA%`, `<Agent exe>`, `StoragePath`, `<InstallRoot>` 기준이 혼재됨 -> 각 기호의 의미, 기본값과 설정으로 변경되는 경로를 구분하고 파일명·경로를 코드 형식으로 표시한다. (Codex, agy, Kimi)
- [생성·변경·삭제 단락] 파일별 재생성과 데이터 유실 여부가 부족함 -> 설정 파일 재생성 조건, `data.db`·레시피·이미지 삭제 시 유실, 설정 적용 시점을 파일별로 명시한다. (Codex, Claude, agy, Kimi)
- [백업·용량 관리] 관리 기준이 지나치게 포괄적임 -> `data.db`, 레시피 JSON, 필요한 이미지·로그를 백업 대상으로 구분하고, 데이터 보존 기간 및 저장 장치 여유 공간을 정기 확인하도록 안내한다. (Codex, Claude, agy, Kimi)

## AI 지적이 부정확 (코드검증)

- agy 수정 전문의 `manager-settings/state.json | 자동 생성 O`는 부정확하다. `manager-settings.json`은 없을 때 메모리 기본값만 사용하며 코드가 파일을 생성하지 않는다. `manager-state.json`은 상태가 실제 저장될 때 생성된다.
- agy 수정 전문의 Agent 로그 “7일이 지난 로그 자동 정리”는 부정확하다. 콘솔 Agent의 Serilog 설정은 기간이 아니라 최근 7개 롤링 파일 보존이다.
- agy 수정 전문의 `data.db`·레시피 파일 “편집 후 런타임 반영”은 코드로 보장되지 않는다. `data.db`는 실행 중 LiteDB가 열고 있으며, 레시피 파일도 저장소 조회 시 읽지만 직접 편집을 공식 적용 절차로 제공하지 않는다.
- Codex가 제안한 `Agent_{CameraIndex}` 매핑 안내는 조건부로만 맞다. 현재 `RecipeEngine`은 `CameraAlias`에 대응하는 등록 장치의 `AgentId`를 우선 사용하고, 실패할 때만 해당 형식으로 대체한다.
- 기존 장 및 agy 초안의 `C:\HeatingCameraSystem\logs\{AgentId}\`을 콘솔 Agent의 기본 로그 위치로 보는 설명은 부정확하다. 이는 AgentManager 감시 경로이며 콘솔 Agent 기본값은 실행 파일 아래 `logs`이다.

## 보류 (설비 안전/도메인 확인 필요)

- 실행 중 `data.db` 교체·복원, Master·Agent·AgentManager 종료 순서와 재가동 확인 절차는 실제 배포 구성에서 검증한 뒤 문서화한다.
- 백업 주기, 이미지·로그 보존량, 최소 디스크 여유 공간은 촬영 빈도와 현장 저장 용량을 확인해 결정한다.
- `<InstallRoot>` 및 로그 경로의 쓰기 권한, 백업본 외부 반출과 민감정보 취급 기준은 현장 보안 정책 확인이 필요하다.
