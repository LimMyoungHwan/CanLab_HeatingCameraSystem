# 11-부록-—-런타임-파일 — 검토 종합 (Round 1)

## 판정

수정 필요. 표의 기본 구조는 유효하지만 일부 파일명·경로·보존 설명이 실제 구현과 다르거나 불충분하다.

## 합의·다수 수정 (코드 확인됨)

- `manager-settings/state.json`을 `manager-settings.json`과 `manager-state.json`으로 분리한다. 둘 다 `<InstallRoot>\Manager\` 아래이며 기본 `InstallRoot`는 `C:\HeatingCameraSystem`이다.
- `%LOCALAPPDATA%`, 실행 파일 폴더, `StoragePath`, `InstallRoot`의 의미와 실제 경로 확인 방법을 설명한다.
- `hardware.json`은 Master 최초 실행 시 생성되며 변경 후 재시작해야 한다.
- 콘솔 Agent의 `agent.json`은 일반 실행 시 exe 폴더에 생성된다. 단, 다중 인스턴스 CLI 실행에서는 파일을 만들지 않고 인수와 기본값을 사용할 수 있다.
- `recipe\*.json`은 현재 레시피의 실제 저장소이고, `data.db`는 레이아웃·촬영/챔버/알람 이력·카메라 설정 등을 저장한다. 두 저장소의 역할을 명확히 분리한다.
- 캡처 이미지를 Agent 원본과 Master 캐시로 분리한다. 콘솔 Agent 기본값은 `<Agent exe>\ImageStorage\`, Master 캐시는 `%LOCALAPPDATA%\HeatingCameraSystem\ImageCache\`이다.
- 파일별 자동 생성 여부, 재시작 필요 여부, 삭제 시 재생성·데이터 유실 여부를 간단히 추가한다.
- `data.db`, 레시피, 이미지, 로그의 백업·용량 관리 안내와 설정 레퍼런스 장의 상호 참조를 추가한다.

## AI 지적이 부정확 (코드검증)

- Agent 로그를 일괄적으로 `C:\HeatingCameraSystem\logs\{AgentId}\`, “NDJSON, 7일 보관”으로 설명하면 부정확하다. 콘솔 Agent 기본 로그는 `<Agent exe>\logs\agent-YYYYMMDD.log`이며 JSON 형식이지만 확장자는 `.log`이고, 보존 기준은 7일이 아니라 최근 파일 7개이다.
- 현재 AgentManager는 Agent/AgentUI 프로세스를 직접 실행하지 않는다. 따라서 `<InstallRoot>\logs\{AgentId}\`는 Manager가 조회하도록 기대하는 경로이지 모든 Agent 로그의 보장된 실제 저장 위치가 아니다.
- AgentUI 로그는 `%LOCALAPPDATA%\HeatingCameraSystem\AgentUI\logs\agentui-*.ndjson`에 일별 생성되고 최근 14개를 보존한다. 현 표의 “Agent 로그” 한 행에는 이 런타임 파일이 누락돼 있다.
- `LogRetentionDays=7` 설정은 선언돼 있으나 실제 로그 정리 코드에 연결되지 않았다. 운영자가 이 값으로 보존 기간을 변경할 수 있다고 안내하면 안 된다.
- `recipe\*.json`을 `data.db`와 중복 저장되는 현재 데이터로 설명하면 안 된다. LiteDB의 레시피는 파일 저장소로 1회 마이그레이션하기 위한 레거시 데이터다.
- `manager-settings.json`은 없을 때 기본값을 메모리에서 사용하지만 코드상 자동 저장하지 않는다. “자동 생성”으로 표시하면 부정확하다.

## 보류 (설비 안전/도메인 확인 필요)

- `data.db`, 설정, 상태 파일의 운영 중 복사·교체 허용 여부와 정식 종료·복구 절차는 설비 운영 정책 확인 후 확정한다.
- 이미지·이력·로그 삭제가 감사 추적 및 장애 분석에 미치는 영향, 실제 보존 주기와 디스크 임계치는 현장 정책 확인이 필요하다.
- `manager-state.json` 삭제 시 승인·카메라 상태가 초기화되는 운영 영향은 AgentManager 재승인 절차와 함께 검증해야 한다.
