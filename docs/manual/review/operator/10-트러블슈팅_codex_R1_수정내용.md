# 10-트러블슈팅 — codex 검토 (Round 1)

## 종합 평가
- 수정 필요도: 상
- 한 줄 요약: 주요 장애 유형은 포함했지만 점검 순서, 정상 판정 기준, 복구 절차와 안전 주의사항이 부족하고 일부 개발자용 표현이 관리자용 조치로 제시되어 있다.

## 수정 필요 항목
1. [전체 표] 문제: 각 행이 확인 대상만 나열하고 있어 관리자가 어떤 순서로 점검하고 확인 결과에 따라 무엇을 조치해야 하는지 알기 어렵다. -> 제안: 각 증상을 `점검 순서`, `정상 기준`, `조치`로 구분하고 서비스 재시작 또는 담당자 이관 조건까지 명시한다.
2. [Agent 초록 점 안 뜸] 문제: “초록 점”이 표시되는 화면과 정상 상태의 의미가 정의되지 않았으며, NATS 연결 실패 시 실제 확인 절차도 없다. -> 제안: 화면 위치를 명시하고 Agent 콘솔 메시지, NATS URL, 서버 가동 여부, 기본 포트 4222의 방화벽·네트워크 연결 순서로 안내한다.
3. [캡처 타임아웃] 문제: “스텝 CameraIndex ↔ AgentId 매칭(4.6)”만으로는 설정 파일과 수정 위치를 찾기 어렵다. -> 제안: 레시피의 `CameraIndex`와 Agent `agent.json`의 `AgentId`를 비교한다고 명시하고, 변경 후 Agent 재시작이 필요함을 안내한다.
4. [캡처 실패] 문제: `frame.Empty()`는 소스 코드 수준의 표현이며 콘솔에 해당 문구가 실제로 출력되는지 불명확하다. -> 제안: 실제 로그에서 확인할 오류 문구를 제시하거나 “프레임이 비어 있다는 오류”처럼 관리자 관점의 표현으로 바꾸고, 드라이버 인식 → USB 연결 → 다른 프로그램의 카메라 점유 순으로 점검하게 한다.
5. [PLC 온습도 0 고정] 문제: 명령의 `<ip>`가 치환값임을 설명하지 않았고 실행 위치, 성공 판정 및 실패 후 조치가 없다. -> 제안: PowerShell에서 `Test-NetConnection <PLC IP> -Port 2004`를 실행한다고 설명하고 `TcpTestSucceeded : True`를 정상 기준으로 제시한다.
6. [값이 이상한 숫자] 문제: “D/M/P 토큰”이 어떤 설정 필드를 뜻하는지 불분명하고, 모든 이상값을 `UseHexBitIndex`나 온도 ÷10 문제로 단정할 수 있다. -> 제안: `hardware.json`의 해당 PLC 디바이스 주소와 `UseHexBitIndex`를 실제 PLC 명세와 대조하도록 하고, ÷10 스케일은 온도값에만 적용된다는 범위를 명확히 한다.
7. [셔터 미응답] 문제: 질문형 문장과 내부 변수명 `_openBuffer/_closeBuffer`는 관리자용 점검 절차로 부적절하다. 실제 전송 바이트나 이를 확인할 방법도 없다. -> 제안: 실제 COM 포트, 포트 점유, 통신 설정을 먼저 확인하게 하고 프로토콜 확인이 필요하면 “ASCII가 아닌 raw binary 명령 사용”과 열기·닫기 바이트값을 별도 기술 점검 항목으로 제시한다.
8. [레시피 ‘챔버 안정화’ 멈춤] 문제: `Tolerance`, `STOP` 등 영문 용어가 화면 또는 설정의 정확한 명칭인지 설명되지 않았고 습도 제어가 실제 안정화 조건에 포함되는지도 불명확하다. -> 제안: 안정화 완료 조건, 허용 오차의 설정 위치, 대기 중 확인할 현재값과 목표값을 명시하고 화면상의 정확한 중지 버튼 명칭을 사용한다.
9. [Devices에 카메라 안 뜸] 문제: `HCS-Manager`, “예약작업”, `Running`, `manager-state.json 엔트리`가 서로 어떤 관계인지 설명되지 않는다. -> 제안: 서비스 실행 상태 → Master와 Manager의 NATS 서버 일치 → 상태 파일 등록 여부 순으로 점검하게 하고, 상태 파일을 직접 수정해야 한다면 먼저 프로세스를 종료하고 백업하도록 경고한다.
10. [승인했는데 Agent 안 뜸] 문제: `SimulationMode면 spawn 안 함`은 원인 설명에 그치며 정상 동작인지 장애인지 구분되지 않는다. -> 제안: 시뮬레이션 모드에서는 Agent 자동 실행을 기대하지 않아야 한다고 명시하고, 실제 운용 모드에서만 `AgentExePath`와 Agent별 로그를 점검하도록 분기한다.
11. [data.db 열 수 없음] 문제: “`*.db-log` 있으면 자동 복구”는 복구 조건과 실패 가능성을 생략한 단정적인 표현이며, 실행 중인 DB 파일을 임의로 조작할 위험이 있다. -> 제안: Master 중복 실행 여부를 먼저 확인하고 모든 Master 프로세스를 정상 종료한 뒤 재실행하도록 안내한다. DB와 로그 파일을 삭제·이름 변경하지 말고, 재실행 후에도 실패하면 파일을 백업하여 관리자에게 전달하도록 명시한다.
12. [표현 일관성] 문제: “일치?”, “점유?” 같은 질문형 표현, 한글·영문 용어 및 경로 표기가 혼재되어 있다. -> 제안: 모든 항목을 명령형 점검 문장으로 통일하고 파일명·필드명·명령·경로는 코드 서식으로 표시한다.

## 누락/추가 제안
- 작업 전 자동 운전을 중지하고 히터, 서보, 셔터 등 하드웨어가 안전한 상태인지 확인하라는 공통 안전 경고를 추가한다.
- 설정 파일 변경 전 백업, 변경 후 재시작 필요 여부, 원래 값으로 복원하는 방법을 공통 절차로 추가한다.
- 로그 수집 시 필요한 파일, 발생 시각, Agent ID, 레시피 단계, 화면 오류 메시지를 기록하도록 안내한다.
- NATS, PLC, 시리얼, 카메라 장애를 구분할 수 있도록 “통신 → 설정 → 장치 점유 → 로그” 순서의 기본 진단 흐름을 추가한다.
- 문제가 해결되지 않을 때 작업을 중단해야 하는 조건과 유지보수 담당자에게 전달할 정보를 명시한다.
- `hardware.json`, `agent.json`, `manager-state.json`, `data.db`, Agent 로그의 실제 위치 또는 해당 위치를 설명한 장 번호를 연결한다.
- 파일을 직접 수정하거나 삭제하기 전에 관련 프로세스를 종료해야 하는 항목을 명확히 표시한다.
