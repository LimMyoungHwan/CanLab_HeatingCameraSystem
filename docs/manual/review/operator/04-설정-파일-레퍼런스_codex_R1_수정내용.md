# 04-설정-파일-레퍼런스 — codex 검토 (Round 1)

## 종합 평가
- 수정 필요도: 상
- 한 줄 요약: 핵심 위치와 기본값은 잘 요약했지만, 설정 레퍼런스로 사용하기에는 실제 필드명·중첩 구조·단위·변경 시 주의사항이 지나치게 축약되어 있고 일부 섹션이 누락되어 있다.

## 수정 필요 항목
1. [4.1 파일 위치] 문제: `manager-settings/state.json`이 하나의 경로 또는 파일명처럼 보여 실제 파일 구성을 판단하기 어렵다. -> 제안: `manager-settings.json`과 `state.json`이 별도 파일이라면 행을 분리하고 각각의 정확한 절대 경로와 용도를 명시한다.
2. [4.1 파일 위치] 문제: `%LOCALAPPDATA%`와 “Agent exe 폴더”의 확인 방법이 없다. -> 제안: 탐색기 주소 표시줄에 `%LOCALAPPDATA%\HeatingCameraSystem`을 입력하는 방법과 실행 파일 기준 상대 경로의 예를 추가한다.
3. [4.1 파일 위치] 문제: `recipe/*.json`의 “자동생성: 예(레시피 저장)”는 최초 실행 시 자동 생성되는 것인지, 사용자가 레시피를 저장할 때 생성되는 것인지 불명확하다. -> 제안: 폴더와 개별 파일의 생성 시점을 구분한다.
4. [4.2 hardware.json — 최상위] 문제: `Plc / Nats / Serial / BlackBody / RecipeEngine`을 “아래 4.3~4.6”에서 설명한다고 했지만 Nats와 Serial 필드 설명이 없고, 4.5~4.6은 `agent.json`과 라우팅 설명이다. -> 제안: 참조 범위를 바로잡고 `Nats`, `Serial` 전용 하위 절을 추가한다.
5. [4.2 hardware.json — 최상위] 문제: `CameraPairings`는 최상위 필드로 소개되지만 배열 요소의 필드명과 페어링 기준이 전혀 설명되지 않는다. -> 제안: 요소별 실제 JSON 필드명, 예시 객체, 카메라와 COM 포트의 식별 기준을 표로 제공한다.
6. [4.2 DataRetentionDays] 문제: “촬영 이미지·이력 보관 일수”만으로는 삭제 대상, 정리 실행 시점, `ImageCache`와 Agent의 `ImageStorage` 포함 여부를 알 수 없다. 운영 데이터 삭제와 관련된 중요한 설정이다. -> 제안: 정확한 정리 대상과 실행 주기, `0`의 의미, 변경 전 백업 주의를 명시한다.
7. [4.3 hardware.json — PLC 주요 필드] 문제: `TempPv/TempSv/TempTarget`, `Eq*`, `Admin*`처럼 여러 필드를 축약해 실제 JSON 키를 그대로 확인하기 어렵다. 특히 주소 목록과 필드의 대응 관계가 모호하다. -> 제안: 실제 필드명을 한 행씩 나누고 각 필드와 기본 주소를 1:1로 표시한다.
8. [4.3 hardware.json — PLC 주요 필드] 문제: `BitJogX±`, `BitJogY±`는 `±`가 실제 필드명인지 축약 표기인지 불명확하다. -> 제안: 양·음 방향의 실제 JSON 키를 각각 적는다.
9. [4.3 hardware.json — PLC 주요 필드] 문제: `UseHexBitIndex`의 “비트 오독 시 반전”은 무엇을 반전해야 하는지 모호하며 잘못된 임의 변경을 유발할 수 있다. -> 제안: XGB 기본값은 `true`임을 유지하고, 실제 PLC 주소 체계 확인 없이 변경하지 말라는 절차형 주의문으로 바꾼다.
10. [4.3 스케일] 문제: `value×10 → short`만 제시되어 소수점 처리 방식, 허용 범위, 음수 및 오버플로 처리 여부를 알 수 없다. -> 제안: 운영자가 입력해야 하는 단위는 ℃/%인지, 저장값 변환은 프로그램이 수행하는지 명시하고 `short` 범위를 넘는 값을 입력하지 않도록 경고한다.
11. [4.3 placeholder 주의문] 문제: 운영 전 반드시 확인해야 할 임의 주소가 기본값 표에 정상 주소와 함께 제시되어 그대로 사용될 위험이 있다. -> 제안: 해당 필드 행에도 “검증 전 사용 금지”를 표시하고, PLC 명세 확인 및 백업 후 변경하도록 강조한다.
12. [4.4 BlackBody / RecipeEngine] 문제: `BlackBody.Units[]` 한 행에 COM 포트, 직렬 설정, IP가 섞여 있어 유닛 객체의 실제 구조와 연결 방식 선택 조건을 알 수 없다. -> 제안: 배열 요소의 실제 필드명과 직렬/IP 연결별 필수값을 구분하고 최소 JSON 예시를 제공한다.
13. [4.4 BlackBody 설정] 문제: `Enabled`와 `Simulated`를 동시에 설정했을 때의 동작 우선순위가 설명되지 않는다. -> 제안: 유효한 조합과 각 조합의 제어 경로를 표로 명시한다.
14. [4.4 RecipeEngine] 문제: `TemperatureTolerance`가 챔버와 흑체에 공통 적용된다고만 되어 있고 안정화 판정 방식이나 유효 범위가 없다. -> 제안: 판정 대상, 단위, 허용 가능한 값 범위와 `0` 또는 음수 입력 시 동작을 명시한다.
15. [4.5 agent.json] 문제: `CameraIndex`를 “OpenCV 카메라 인덱스 + 토픽 매칭 키”로 표현해 카메라 장치 선택과 Agent 라우팅 식별자가 항상 같은 값이어야 하는 것으로 오해할 수 있다. -> 제안: 수동 구성에서 `AgentId=Agent_<CameraIndex>` 정합성이 필요한 이유와 OpenCV 장치 인덱스의 역할을 분리해 설명한다.
16. [4.5 StoragePath] 문제: 상대 경로만 설명하고 절대 경로 허용 여부, 폴더 자동 생성 여부, 쓰기 권한 실패 시 동작을 안내하지 않는다. -> 제안: 지원되는 경로 형식과 권한 확인 절차를 추가한다.
17. [4.6 매핑] 문제: “수동 Agent”와 “Manager가 부여한 Agent”의 구분 및 `CameraAlias`를 찾는 DB/관리 화면이 설명되지 않아 관리자가 어떤 방식을 적용해야 하는지 판단하기 어렵다. -> 제안: 두 라우팅 방식의 적용 조건, 필수 설정값, Alias 등록·확인 위치를 단계별로 정리한다.
18. [4.6 매핑] 문제: 토픽 이름이 일반 텍스트로 표시되어 설정값과 설명 문장을 구분하기 어렵다. -> 제안: `master.cmd.capture.Agent_{CameraIndex}`, `Agent_<CameraIndex>`, `CameraAlias`를 코드 서식으로 통일한다.
19. [전체 구성] 문제: 설정 파일을 언제 편집해야 하는지, 실행 중 편집 가능한지, 잘못된 JSON의 영향과 복구 방법이 없다. -> 제안: 프로그램 종료 → 파일 백업 → UTF-8 JSON 편집 → 재시작 → 연결 및 로그 확인의 공통 변경 절차를 앞부분에 추가한다.

## 누락/추가 제안
- `hardware.json`, `agent.json`의 최소 전체 JSON 예시를 각각 추가한다.
- 누락된 `Nats`, `Serial`, `CameraPairings` 필드 레퍼런스를 추가한다.
- JSON에서는 주석과 후행 쉼표를 사용할 수 없다는 편집 주의사항을 추가한다.
- 설정 변경 전 원본 파일 백업, 변경 후 프로그램 재시작, 연결 상태 확인 절차를 추가한다.
- 비밀번호나 토큰 등 민감한 NATS 설정이 존재한다면 설정 파일 공유 및 로그 첨부 시 마스킹 지침을 추가한다.
- PLC placeholder 주소는 장비별 검증 완료 여부를 기록할 수 있는 점검표와 연결하는 것이 좋다.

## 이미지 자리 검토
- 이미지 자리 없음 — 필드 표 중심의 레퍼런스 장이므로 필수 이미지는 아니지만, `%LOCALAPPDATA%` 폴더 확인과 `agent.json` 위치 확인이 어려운 독자를 위해 탐색기 경로 예시 화면 1개 정도는 유용하다.
