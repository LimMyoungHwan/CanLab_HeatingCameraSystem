• # 02-시스템-아키텍처 — kimi 검토 (Round 1)

  ## 종합 평가
  - 수정 필요도: 중
  - 한 줄 요약: 구성요소·NATS 토픽 표 자체는 정확하고 간결하나, "아키텍처" 챕터로서 통신 경로(포트/프로토콜)·데이터 흐름·NATS 서버 위치가 빠져 있어 설치 관리자가 실제 배선/방화벽 작업에 쓰기에는 정보가 부족함.

  ## 수정 필요 항목
  1. [2.2 토픽 표] 문제: 토픽 접두사가 `master.*`, `agent.*`, `agent-mgr.*`, `server.cmd.mgr.*`로 제각각인데 아무 설명이 없음. 특히 `server.cmd.mgr`은 방향이 "Master→Manager"인데 접두사가 `server`라서 독자가 "서버"라는 별도 컴포넌트가 있다고 오해할 수 있음 -> 제안: 표 아래에 "접두사 `server.cmd.mgr`은 Master가 발행하는 Manager 제어 토픽" 같은 한 줄 주석 추가, 또는 방향 열 기준으로 일관성 있게 정리.
  2. [2.2 AgentId 형식 문단] 문제: "CameraAlias→DB조회→AgentId 변환"에서 DB가 처음 등장하는데 무엇을 가리키는지(어느 PC의 어떤 DB인지) 설명이 없고, "HardwareId해시8"도 어떤 하드웨어 식별자인지 불명 -> 제안: DB의 위치(예: Master PC의 로컬 DB)와 하드웨어 ID의 출처를 한 문장으로 보강.
  3. [2.1 구성 표] 문제: `AgentManager` 행의 "로그온 예약작업"이 무엇을 의미하는지 설치 관리자에게 불명(윈도우 작업 스케줄러 등록을 뜻하는지) -> 제안: "Windows 작업 스케줄러(로그온 시 자동 시작)"처럼 풀어서 기술.
  4. [2.2 토픽 표] 문제: `agent-mgr.inventory.{PCId}`의 "내용"이 "카메라 목록·상태"인데, 이 토픽이 Manager의 감독 결과를 Master에 보고하는 용도인지, 주기적 전송인지(하트비트처럼 주기 명시 없음) 표기가 다른 행과 불균일 -> 제안: `agent.status`처럼 전송 주기 또는 발생 조건을 명시하거나, 주기가 아니라면 "이벤트 발생 시" 등으로 표기.

  ## 누락/추가 제안
  - **NATS 서버(브로커) 자체가 2.1 구성 표에 없음.** 어느 PC에서 NATS 서버가 구동되는지는 설치 시 가장 먼저 결정해야 할 사항이므로 구성 요소에 추가하거나 별도 문단으로 명시 필요.
  - **통신 포트/프로토콜 요약 누락.** 설치 관리자 입장에서 방화벽 개방이 필수인데, NATS(기본 4222), PLC XGT FEnet(TCP 2004), 시리얼(셔터 제어) 등의 포트·연결 대상 정리 표가 없음. `## 2.3 통신 경로 및 포트` 같은 섹션 추가 권장.
  - **PLC·시리얼 셔터 연결이 챕터 전체에서 언급되지 않음.** "시스템 아키텍처"인데 Master↔PLC(FEnet), Master↔시리얼 셔터 경로가 빠져 있어 그림 1(네트워크·설비 구성도)과 대응되는 본문 설명이 없음.
  - **전체 데이터 흐름 요약 부재.** "레시피 실행 → 캡처 명령 → Agent 캡처 → 결과 반환 → Master 저장/표시" 같은 1~2줄 흐름 설명이 있으면 뒤의 토픽 표 이해가 쉬워짐.
  - **연결 실패/재시도 동작 요약 부재.** 유지보수 관리자 대상 챕터이므로 "NATS는 자동 재연결, PLC/시리얼은 주기적 점검 후 재연결" 수준의 한두 줄 언급이 유용함.

  ## 이미지 자리 검토
  - [그림 1] 적절 — 위치(구성 표 직후)와 목적은 타당. 다만 "캡처 대상"이 "설비 문서의 구성도 **또는** 현장 배치 사진"으로 두 가지인데 둘은 정보 성격이 다르므로(구성도=논리 연결, 사진=물리 배치) 하나로 확정하거나 두 장으로 분리할지 명시 필요. 또한 본문에 포트/연결 경로 설명이 없어 그림에 어떤 정보(IP 대역, 케이블 종류, 포트 번호 등)를 표기해야 하는지 기준이 없으므로, 캡처 지시에 "각 연결 선에 프로토콜·포트 표기" 같은 요구사항을 추가하면 좋음.
