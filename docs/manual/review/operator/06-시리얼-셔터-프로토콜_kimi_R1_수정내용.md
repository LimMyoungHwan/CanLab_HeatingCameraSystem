• # 06-시리얼-셔터-프로토콜 — kimi 검토 (Round 1)

  ## 종합 평가
  - 수정 필요도: 상
  - 한 줄 요약: 프로토콜 바이트 스펙 자체는 정확하지만, 대상 독자(설치·설정·유지보수 관리자)에게 필요한 연결 설정·절차·문제 해결 정보가 전무해 "챕터"로서 기능하지 못하는 수준.

  ## 수정 필요 항목
  1. [전체 구성] 문제: 챕터가 본문 6줄로 끝나며, 제목 "# 6. 시리얼 셔터 프로토콜" 아래에 도입부(셔터의 역할, 시스템 내 위치, Agent PC의 어느 카메라와 연결되는지)가 없음. -> 제안: "개요" 섹션을 추가해 셔터가 왜 필요한지(캡처 시 광학 노출 차단/보정 목적 등 실제 용도), Master가 아닌 Agent PC에서 제어된다는 위치 관계를 2~3문장으로 서술.

  2. [연결 설정 누락] 문제: 시리얼 포트 설정이 전혀 언급되지 않음. 시스템은 `SerialSettings`(기본값 COM3, 9600 8N1)를 사용하며 이는 실제 카메라 가상 포트에 맞게 수정이 필요한 플레이스홀더임에도, 설정 파일 위치(`hardware.json`, `%LOCALAPPDATA%\HeatingCameraSystem\`)와 항목명·기본값·수정 절차가 빠져 있음. -> 제안: "연결 설정" 섹션 추가 — 포트명/보드레이트/데이터비트/패리티/스톱비트, 설정 파일 경로와 편집 후 재시작 필요 여부 명시.

  3. [프로토콜 표] 문제: 바이트 열이 코드 블록 주석 "(3번째 바이트만 0x01/0x00 차이)"로만 설명되어 바이트 인덱스 기준(0부터? 1부터?)이 모호하고, 각 바이트의 의미(헤더? 명령? 체크섬?) 설명이 없음. -> 제안: 바이트별 표(Byte 0~6, 값, 의미) 형태로 정리하고 "3번째"가 0-based인지 명확히. 응답 프레임 존재 여부(ACK 있는지)도 명시 — 없다면 "응답 없음, 송신 전용"이라고 써야 함.

  4. [상태 조회 미지원] 문제: "마지막 명령 기준 소프트웨어 캐시 반환"은 중요한 운영 함의(Agent 재시작·전원 재인가 시 실제 셔터 상태와 캐시가 어긋날 수 있음)가 설명 없이 한 줄로 끝남. -> 제안: 주의사항으로 "프로그램 재시작 후 첫 명령 전까지 표시 상태가 실제와 다를 수 있으므로, 시작 시 셔터 닫기(또는 열기) 명령을 한 번 보내 상태를 동기화할 것" 같은 운영 지침 추가.

  5. [다른 셔터 모델 절차] 문제: "Protocols/SerialShutterController.cs의 _openBuffer/_closeBuffer 수정 후 재배포"는 개발자 대상 지시이며, 파일 전체 경로(`HeatingCameraSystem.Protocols/SerialShutterController.cs`), 빌드·배포 방법(어떤 exe를 어느 PC에 재배포하는지)이 없음. 유지보수 관리자가 소스를 수정한다는 전제 자체가 위험. -> 제안: "버퍼 변경은 소스 수정이 필요한 개발 작업"임을 명시하고, 간단한 빌드/배포 경로(`dotnet build` → Agent PC의 실행 폴더로 DLL 교체) 또는 개발 담당자 에스컬레이션 안내로 보완.

  6. [문제 해결 섹션 부재] 문제: "셔터가 동작하지 않을 때" 확인 항목(COM 포트 번호 확인, 다른 프로그램이 포트 점유 중인지, 케이블/가상 포트 드라이버 등)이 없음. -> 제안: 짧은 트러블슈팅 표(증상 → 확인 사항) 추가.

  ## 누락/추가 제안
  - 셔터 명령이 어느 흐름에서 발생하는지(레시피 캡처 시 자동? 수동 버튼?) 한 단락 — 관리자가 "정상 동작"을 판별할 기준 제공.
  - 수동 테스트 방법(예: 장치 관리자에서 포트 확인, 시리얼 터미널로 바이트 송신 테스트) — 설치 검증 절차로 유용.
  - 관련 매뉴얼 내 교차 참조(캡처 흐름 챕터, `hardware.json` 설정 챕터).

  ## 이미지 자리 검토
  - 챕터에 📷 [그림 N] 블록이 하나도 없음 — 부적절. 다음 자리에 이미지 추가 권장:
    - [그림 1] 셔터 하드웨어–Agent PC 연결도(USB-시리얼 변환 또는 가상 COM 포트 포함) — 개요 섹션.
    - [그림 2] Windows 장치 관리자에서 해당 COM 포트가 잡힌 화면 캡처 — 연결 설정/트러블슈팅 섹션.
  - 바이트 프로토콜 자체는 텍스트 표로 충분하므로 별도 그림 불필요.
