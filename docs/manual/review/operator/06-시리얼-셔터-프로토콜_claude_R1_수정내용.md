# 06-시리얼-셔터-프로토콜 — claude 검토 (Round 1)

## 종합 평가
- 수정 필요도: 중
- 한 줄 요약: 바이트 값·주석은 SerialShutterController.cs와 정확히 일치하나, 관리자가 실제로 손댈 연결 설정(포트/보레이트) 안내와 이미지 자리가 전혀 없어 완결성이 부족함.

## 수정 필요 항목
1. [전체] 문제: 시리얼 포트 연결 파라미터(PortName, BaudRate, DataBits, Parity, StopBits)에 대한 언급이 전혀 없음. 02-configuration.md §2.3에 이미 정의돼 있는 `hardware.json`의 `Serial` 섹션(포트명 `COM3`, 보레이트 `9600` 등)을 참조하지 않으면 관리자가 셔터 통신 자체를 설정할 방법을 이 챕터만 봐서는 알 수 없음 -> "연결 설정은 §2.3 hardware.json Serial 섹션 참고" 식의 상호 참조 추가.
2. [마지막 줄] 문제: "수정 후 재배포"라고만 돼 있어 실제 절차(빌드 → 테스트 → 배포 방법)가 불명확함. 02-configuration.md 205~207행에는 `dotnet test --filter SerialShutter`로 검증하라는 절차가 있는데 이 챕터엔 빠짐 -> 최소한 "수정 후 단위 테스트(`dotnet test --filter SerialShutter`) 통과 확인 후 재배포" 정도로 구체화.
3. [상태 조회 설명] 문제: "소프트웨어 캐시 반환"이 프로그램 재시작 시 초기값이 무엇인지(닫힘으로 간주되는지) 언급 없음. 실제 코드상 `_isOpen` 필드 기본값은 `false`(닫힘) -> 재시작 직후엔 실제 하드웨어 상태와 무관하게 "닫힘"으로 표시된다는 점 명시 필요.

## 누락/추가 제안
- 시뮬레이션 모드에서는 `FakeSerialShutterController`가 실제 바이트 전송 없이 호출만 기록한다는 내용(02-configuration.md 210행)이 있음 — 유지보수 관리자가 현장 테스트와 시뮬레이션 결과를 혼동하지 않도록 한 줄 추가 권장.
- 다른 셔터 모델 대응 시 "카메라별 시리얼 설정을 NATS로 원격 전송"하는 Master Settings 탭 기능(02-configuration.md 75행)과의 관계 — 이 챕터가 다루는 게 원격 설정이 아니라 로컬 `hardware.json` 고정값이라는 점을 한 문장으로 구분해주면 좋음.
