# 06-시리얼-셔터-프로토콜 — 검토 종합 (Round 1)

## 판정

수정 필요도 **중**. 7바이트 명령값은 코드와 일치하지만, 운영상 주의사항과 설정·검증 안내가 부족하다.

## 합의·다수 수정 (코드 확인됨)

- 명령 설명을 코드 블록 밖으로 분리하고, 차이는 **왼쪽 세 번째 바이트(오프셋 2)**라고 명시한다.
- `cameraIndex`는 식별자일 뿐 전송 버퍼에는 포함되지 않는다고 설명한다.
- 상태값은 `_isOpen` 소프트웨어 캐시이며 실제 셔터 상태를 보장하지 않는다. 재시작 직후 기본값은 `false`(닫힘)이다.
- 다른 모델은 버퍼만 바꾸면 된다고 단정하지 말고 제조사 프로토콜·통신 조건 확인, 빌드·테스트·실장비 검증 후 재배포하도록 수정한다.
- 소스 경로를 `HeatingCameraSystem.Protocols/SerialShutterController.cs`로 바로잡는다.
- `SerialSettings`의 포트·보레이트 등 연결 설정 장을 상호 참조한다.
- 설치·설정 변경 후 열기와 닫기를 각각 실행하고 실제 동작을 확인하도록 안내한다.

## AI 지적이 부정확 (코드검증)

- agy의 “`cameraIndex`별 개별 포트로 전송” 설명은 부정확하다. 구현은 하나의 `_port`에 동일한 버퍼를 쓰며 `cameraIndex`를 사용하지 않는다.
- “통신 실패 시 캐시가 갱신된다”는 해석은 부정확하다. `_port.Write()`가 예외를 던지면 이후 캐시 대입은 실행되지 않는다. 다만 전송 성공 후 기계적 미동작은 감지하지 못한다.
- 프레임 도해나 이미지가 필수라는 지적은 과도하다. 현재 7바이트 명령은 텍스트 표기로 충분하다.

## 보류 (설비 안전/도메인 확인 필요)

- RS-232인지 가상 COM인지, 수동 조작 가능 여부와 육안 확인 절차는 실제 장비 명세 및 현장 안전 절차 확인이 필요하다.
- 다른 셔터 모델의 명령 길이·응답·통신 조건은 제조사 프로토콜 확인 전 확정할 수 없다.
- 자동 재연결 주기와 시뮬레이션 모드 설명은 유용하지만 본 장 포함 범위는 매뉴얼 구성 정책에 따라 결정한다.
