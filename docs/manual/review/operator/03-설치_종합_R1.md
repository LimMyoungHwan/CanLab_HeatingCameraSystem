# 03-설치 — 검토 종합 (Round 1)

## 판정

수정 필요. 설치 흐름은 유효하지만 실행 위치·파일명·설정 키·검증 문구를 실제 구현과 일치시켜야 한다. Kimi는 기권했다.

## 합의·다수 수정 (코드 확인됨)

- 명령은 저장소 루트에서 실행한다고 명시하고, publish 대상은 `.csproj` 경로로 표기한다.
- 현재 배포는 프레임워크 종속이다. 빌드 PC는 .NET 8 SDK, Master PC는 Windows Desktop Runtime 8, Agent PC는 .NET Runtime 8이 필요하다.
- Agent 실행 파일명은 `Agent.exe`가 아니라 `HeatingCameraSystem.Agent.exe`이다.
- `hardware.json`의 실제 핵심 키는 `Plc.IpAddress`, `Plc.Port`, `Nats.Url`, `Serial.PortName`이다. 파일은 `%LOCALAPPDATA%\HeatingCameraSystem\`에 생성되며 수정 후 재시작해야 한다.
- `agent.json`은 Agent 실행 폴더에 생성된다. `AgentId`, `CameraIndex`, `NatsUrl`, `StoragePath`, `SimulationMode`를 확인하고 재실행하도록 절차화한다. `SimulationMode`는 JSON boolean `true`/`false`이다.
- CLI 인수는 `<AgentId> <NatsUrl> [CameraIndex] [StoragePath] [SimulationMode] [LogPath]` 순서다. 인스턴스별 Agent ID와 저장 경로를 분리해야 한다.
- 방화벽은 NATS 호스트 4222 인바운드, Master/Agent 4222 아웃바운드, Master 2004 아웃바운드로 구분한다. 원격 PC에서는 실제 NATS 주소로 검사한다.
- Compose는 4222·8222를 매핑하고 `restart: unless-stopped`를 사용한다. 다만 현재 Compose에는 NATS 모니터링 활성화 옵션이 없어 8222 매핑만으로 대시보드가 동작한다고 안내하면 안 된다.
- 장치 관리자만으로 OpenCV `CameraIndex`를 확정할 수 없다. 실제 Agent 로그·미리보기·시험 캡처로 확인한다.
- 실제 로그는 `Connected to NATS (...)`와 `Camera idx=N ready (SIM|REAL)`이다. 문서의 `Camera ready`는 정확하지 않다.
- `dotnet --info 8.x` 대신 `dotnet --list-runtimes`로 Master의 `Microsoft.WindowsDesktop.App 8.x`, Agent의 `Microsoft.NETCore.App 8.x`를 확인한다.
- Master 인식은 대시보드의 Agent ID, `CAM-NN`, 카메라 상태를 확인한다. 오프라인 판정은 마지막 하트비트 후 15초이다.
- 셔터는 문자열 명령이 아닌 7바이트 raw binary 프로토콜이므로 Master 기능으로 검증한다.

## AI 지적이 부정확 (코드검증)

- 그림 1은 2장에 이미 존재한다. 3장이 그림 2부터 시작하는 것은 전체 매뉴얼 연속 번호 체계와 일치한다.
- CLI 인수를 주면 `agent.json`을 읽지 않는다는 지적은 틀리다. 파일이 있으면 먼저 읽고 제공된 인수만 덮어쓴다.
- `NatsUrl`, `PlcSettings.IpAddress`, `SerialSettings.PortName`은 `hardware.json`의 실제 경로가 아니다.
- `nats-server.exe` 단독 실행, Windows 서비스 등록, 자동 시작은 현재 저장소에 제공된 설치 기능이 아니다. 지원 절차로 단정해 추가하지 않는다.
- 8222 접속 주체는 Master PC로 고정되어 있지 않다.

## 보류 (설비 안전/도메인 확인 필요)

- `BitEmergencyStop`, `ServoSpeedPercent`, `BitJogYPlus/Minus`, `ServoPointYBase`는 코드상 현장 확인이 필요한 플레이스홀더다. PLC 명세와 대조하기 전 자동운전·서보 쓰기 시험을 금지해야 한다.
- 실제 PLC·셔터·서보 검증은 비상정지 상태와 작업 구역 안전을 확인하고 현장 승인 절차에 따라 수행한다.
- 8222 외부 공개 범위, 자동 시작 방식, 비-Docker NATS 운영 방식은 현장 보안·운영 정책 확정 후 문서화한다.
