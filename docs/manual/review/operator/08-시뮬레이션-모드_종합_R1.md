# 08-시뮬레이션-모드 — 검토 종합 (Round 1)

## 판정

- Codex: 수정 필요도 상. 설정 경로·필드·재시작·E2E 전제조건 보강 의견은 타당하나, 상당 부분이 현재 원고에 이미 반영됨.
- Claude: 수정 필요도 상. E2E 실행·판정 기준 보강에는 동의하나 `agent.json` 경로와 Docker 필수 여부 일부가 부정확함.
- agy: 수정 필요도 상. 내부 Fake와 외부 Simulator의 구분 제안은 타당하나, 일부 구현체 설명과 CLI 예시는 현재 코드와 정확히 구분해야 함.
- Kimi: 수정 필요도 상. 모드 전환 절차와 실카메라 동작 설명 보강에 동의하나, 별도 웹캠 설정이 있다는 취지의 제안은 부정확함.
- 종합: 네 리뷰는 “운영 가능한 절차와 판정 기준 보강”에 수렴함. 현재 원고에는 경로, 필드명, 재시작, Simulator 명령, E2E 옵션·성공 기준, 복구 절차가 이미 반영되어 있음. 이미지 적절성만 Codex·Claude·agy는 적절, Kimi는 설명 부족으로 부적절 판정하여 경미하게 충돌함.

## 합의·다수 수정 (코드 확인됨)

- [시나리오 표] 설정 파일과 값의 의미가 모호함 -> 현재와 같이 `hardware.json SimulationMode=<값>`과 `agent.json SimulationMode=<값>`을 분리하고 PLC·셔터·카메라의 실제/Fake 범위를 명시한다. Master는 `SimulationMode=true`일 때 Fake PLC·셔터·카메라/페어링·흑체를, Agent는 Fake 카메라 캡처·셔터를 사용한다. (Codex, agy, Kimi)
- [설정 파일 위치] 실제 편집 위치가 필요함 -> `hardware.json`은 `%LOCALAPPDATA%\HeatingCameraSystem\`, `agent.json`은 Agent 실행 파일 폴더임을 유지한다. 두 파일 모두 없으면 기본 설정이 생성된다. (Codex, Claude, agy, Kimi)
- [모드 전환] 설정 적용·복귀 절차가 필요함 -> 설정을 읽는 Master 또는 Agent를 재시작하고, 시험 전 두 설정 파일을 백업하며 시험 후 운영값과 PLC/NATS 주소를 복원하도록 유지한다. (Codex, Claude, Kimi)
- [외부 Simulator] 내부 Fake와 외부 프로토콜 Simulator의 차이가 불명확함 -> Master의 내부 시뮬레이션을 끄고 PLC 주소를 Simulator로 지정하며, 별도 Simulator가 XGT FEnet TCP와 NATS 카메라 경계를 제공한다고 명시한다. (Codex, agy)
- [외부 Simulator 실행] 실행·설정 생성 방법이 필요함 -> 저장소 루트의 PowerShell에서 `start-external-simulator.ps1`을 실행하고, `simulator.json`이 없으면 `simulator.example.json`을 복사해 생성하며 `-ConfigPath`를 지원한다고 유지한다. (Claude, agy)
- [Simulator 제어] 장애·상태 변경 방법이 필요함 -> 코드가 지원하는 `status`, `plc online/offline`, `plc fault <0-19> on/off`, `camera <AgentId> online/fault/offline`, `quit`만 안내한다. (agy)
- [E2E 스크립트] 경로만으로는 실행과 판정이 어려움 -> .NET 8 SDK, 접근 가능한 NATS, 저장소 루트 실행을 전제로 명시하고 각 스크립트의 검증 범위·옵션을 구분한다. (Codex, Claude, agy, Kimi)
- [E2E 성공 판정] 결과 해석이 필요함 -> 드라이버의 `*** PASS ***`와 종료 코드 `0`을 정상 기준으로 유지하고, Manager E2E의 `1=FAIL`, `2=NATS 연결 실패`, `3=timeout`을 명시한다. (Codex, Claude, agy, Kimi)
- [그림 11] PASS 화면의 검증 범위가 부족함 -> 실행한 스크립트명, `*** PASS ***`, 캡처 수량 및 검증 범위가 함께 보이도록 캡처 지침을 유지한다. (Codex, Claude, agy, Kimi)

## AI 지적이 부정확 (코드검증)

- Claude는 `hardware.json`과 `agent.json`의 위치를 모두 `%LOCALAPPDATA%\HeatingCameraSystem\`으로 볼 수 있게 기술했으나, 실제 `agent.json`은 `AppDomain.CurrentDomain.BaseDirectory`, 즉 Agent 실행 파일 폴더에 생성·로드된다.
- Claude·agy는 내부 Fake E2E에 Docker Compose가 필수인 것처럼 제안했으나, `run-e2e-simulation.ps1`의 필수조건은 `nats://127.0.0.1:4222`에서 접근 가능한 NATS이다. 해당 스크립트는 Docker를 직접 기동하지 않는다. `-StartNatsDocker`는 외부 Simulator E2E에만 존재한다.
- agy의 제안문은 `FakeCameraCaptureService`를 Master 내부 Fake 구현체처럼 묶었으나, 이 구현체는 Agent에서 사용된다. Master는 `FakeLiveThermalCamera`, `FakeCameraSerialClient`, `FakeCameraComPairingService`를 사용한다.
- Kimi의 “웹캠 구성이 별도 설정” 주장은 코드와 맞지 않는다. `SimulationMode=false`인 Agent는 `CameraIndex`로 OpenCV `VideoCapture`를 열며, 웹캠 전용 설정 필드는 없다.
- agy가 제시한 Agent CLI 예시는 코드상 유효하지만 `agent.json`을 영구 수정하는 방식은 아니다. 다섯 번째 인수가 실행 중 `SimulationMode`를 덮어쓸 뿐 파일에 저장하지 않는다.

## 보류 (설비 안전/도메인 확인 필요)

- 실제 PLC·셔터·카메라가 연결된 상태에서 시험할 때 필요한 물리적 격리, 운전 허가, 비상정지 및 생산 데이터 보호 절차는 설비 책임자의 확인이 필요하다.
- 운영 복귀 시 사용할 실제 PLC/NATS 주소·포트와 카메라 인덱스는 현장 구성값이므로 문서에서 임의로 제시하지 않는다.
- `SimulationMode=false`에서 선택한 OpenCV 장치가 웹캠인지 실제 열화상 카메라인지는 설치 장비와 드라이버 구성을 확인해야 한다.
