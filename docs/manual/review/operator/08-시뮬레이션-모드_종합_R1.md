# 08-시뮬레이션-모드 — 검토 종합 (Round 1)

## 판정

**수정 필요도: 상.** 세 검토자가 공통으로 설정 필드·파일 위치·실행 전제조건·성공 판정·운영 복귀 절차가 부족하다고 판단했으며, 코드 확인 결과 대부분 타당하다.

## 합의·다수 수정 (코드 확인됨)

- 시나리오 표에 두 파일의 정확한 설정을 각각 명시한다.
  - 운영: `hardware.json`과 `agent.json`의 `SimulationMode=false`
  - 전체 시뮬레이션: 두 파일 모두 `SimulationMode=true`
  - 하이브리드: `hardware.json=true`, `agent.json=false`
- 파일 위치를 정확히 안내한다.
  - `hardware.json`: `%LOCALAPPDATA%\HeatingCameraSystem\`
  - `agent.json`: Agent 실행 파일 폴더
- `hardware.json`은 Master 시작 시, `agent.json`은 Agent 시작 시 읽으므로 변경 후 해당 프로세스를 재시작한다고 명시한다.
- 내부 시뮬레이션 범위를 구분한다. Master는 PLC·셔터·카메라/페어링·흑체를 Fake로 교체하고, Agent는 카메라·셔터를 Fake로 교체한다. NATS 서버는 시뮬레이션되지 않는다.
- 외부 Simulator는 Master 내부 시뮬레이션을 끄고 PLC 주소를 Simulator로 지정해 XGT FEnet과 NATS 카메라 경계를 검증한다고 설명한다.
- `start-external-simulator.ps1` 실행법과 `simulator.json` 자동 생성, `status`, `plc online|offline`, `plc fault`, `camera`, `quit` 명령을 추가한다.
- 세 E2E 스크립트별 역할·전제조건·실행 위치·옵션·성공 기준을 명시한다. 정상 판정은 드라이버의 `*** PASS ***`와 종료 코드 `0`이며, Manager E2E는 `1=FAIL`, `2=NATS 연결 실패`, `3=timeout`을 사용한다.
- 설정 백업·복원, 시험 종료 후 운영값과 PLC/NATS 주소 원복, 트러블슈팅 장 연결을 추가한다.
- 그림 11에는 스크립트명, `*** PASS ***`, 캡처 수량과 검증 범위가 함께 보이도록 한다.

## AI 지적이 부정확 (코드검증)

- Claude의 `agent.json`이 `%LOCALAPPDATA%\HeatingCameraSystem\`에 있다는 표현은 잘못이다. Agent 실행 파일 폴더에 생성된다.
- `run-e2e-simulation.ps1`에 Docker Compose가 필수라는 지적은 과도하다. 필수 조건은 `nats://127.0.0.1:4222`에서 접근 가능한 NATS이며, Docker는 한 가지 기동 방법일 뿐이다.
- 모든 스크립트가 동일하게 `*** PASS ***`를 직접 출력하는 것은 아니다. PowerShell 래퍼가 아니라 실행되는 E2E Driver가 출력하므로 종료 코드도 함께 판정해야 한다.
- `hardware.json SimulationMode=true`가 PLC·셔터만 Fake로 만든다는 설명은 현재 구현과 불일치한다. Master의 카메라/페어링과 흑체도 Fake 구현으로 전환된다.

## 보류 (설비 안전/도메인 확인 필요)

- 실제 설비 연결을 차단한 뒤 시험해야 하는지, 운영 복귀 시 어떤 승인·점검 절차가 필요한지는 현장 안전 책임자의 확인 후 경고문으로 확정한다.
- 외부 Simulator가 실제 흑체 직접통신, COM 포트, USB/DirectShow 장치 및 AgentUI 실시간 영상까지 검증한다는 표현은 피하고, 설비 담당자가 요구 범위를 확인한 뒤 제한사항을 확정한다.
