# 03-설치 — claude 검토 (Round 1)

## 종합 평가
- 수정 필요도: 중
- 한 줄 요약: 구조·순서는 양호하나 그림 번호 누락, 서비스 상시구동(자동시작) 안내 부재, hardware.json 수정 항목 예시 부족 등 유지보수 관리자 관점의 완결성 보완 필요.

## 수정 필요 항목
1. [전체 그림 번호] 문제: 챕터가 [그림 2]부터 시작하고 [그림 1]이 없음 -> 제안: 3.1 사전 요구사항 또는 3.2 방화벽 구간에 [그림 1](예: 사전 준비물 스크린샷 또는 전체 설치 흐름도)을 배치하거나, 번호가 이전 챕터(2장)에서 이어지는 것이라면 각주로 명시.
2. [3.4 Master 설치] 문제: "hardware.json을 실제 환경(PLC IP/NATS URL 등)으로 수정" 부분이 실제 필드명 없이 추상적으로 서술됨 -> 제안: 수정해야 할 최소 키(예: `Plc.IpAddress`, `Nats.Url` 등 실제 필드명)를 코드블록 예시로 제시.
3. [3.4/3.5 Master·Agent 설치] 문제: 실행 후 "재시작" 안내만 있고, 운영 환경에서 PC 재부팅 시 자동 실행(Windows 서비스 등록, 시작프로그램 등록 등) 방법이 없음 -> 제안: 유지보수 관리자 대상 챕터이므로 자동시작/서비스 등록 절차(또는 "수동 실행만 지원" 명시) 추가.
4. [3.7 설치 검증 체크리스트] 문제: 7번 항목만 "(실PLC)" 접두어가 붙어 표기 형식이 다른 행과 불일치 -> 제안: "비고" 컬럼을 추가해 조건부 항목을 표기하거나 동일한 서식으로 통일.
5. [3.3 NATS 서버] 문제: `docker compose -f docs/deployment/docker-compose.yml up -d` 명령이 리포지토리 루트 기준 상대경로인데, 이 챕터 어디에도 "리포지토리를 clone/배포 받은 위치에서 실행" 같은 전제가 없음 -> 제안: 명령 실행 위치(작업 디렉터리) 명시.

## 누락/추가 제안
- Docker를 쓰지 않는 NATS 설치(예: 바이너리/Windows 서비스) 대안이 전혀 없음. 3.1에서 "Docker 권장"이라 했으므로 비-Docker 환경 지원 여부만이라도 한 줄 명시.
- 3.6에서 COM 포트 확인 후 agent.json의 어느 필드에 매핑되는지(예: `ShutterPort`) 명시 필요 — CameraIndex는 필드명이 나와 있으나 COM 포트 쪽은 필드명 누락.
- 방화벽(3.2) 표에 Agent→PLC 통신이 없는 이유(설계상 Master만 PLC와 통신)를 짧게 각주로 언급하면 오해 방지에 도움.
- 설치 후 실패 시 트러블슈팅(예: NATS 연결 실패, PLC Timeout) 안내가 이 챕터에 없음 — 별도 챕터에 있다면 상호참조 링크만이라도 추가.

## 이미지 자리 검토
- [그림 2] NATS 서버 기동 확인 — 적절. 명령 실행 결과와 직접 연결됨.
- [그림 3] hardware.json 생성 위치 — 적절. 최초 실행 확인 포인트로 유용.
- [그림 4] 장치관리자 카메라·COM 확인 — 적절.
- [그림 5] Agent 콘솔 로그 — 적절.
- [그림 6] Master Agent 인식 — 적절하나, "표시 영역: 창 오른쪽" 필드가 다른 그림 항목엔 없는 추가 항목이라 템플릿 일관성 낮음 — 필요시 전체 그림 항목에 "표시 영역" 필드를 통일 적용 권장.
