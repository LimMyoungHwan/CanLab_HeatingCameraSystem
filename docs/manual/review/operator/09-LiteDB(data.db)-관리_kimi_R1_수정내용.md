• # 09-LiteDB(data.db)-관리 — Kimi 검토 (Round 1)

  ## 종합 평가
  - 수정 필요도: 상
  - 한 줄 요약: data.db 경로와 백업·초기화 개념은 정확하지만, 운영 매뉴얼로서 복원 절차, 상세 단계, 주의사항, 레시피 폴더 경로 등 실무에 필요한 핵심 내용이 대부분 누락되어 있음.

  ## 수정 필요 항목
  1. [전체 구조] 문제: 섹션 구분 없이 4개 불릿과 코드 블록만 나열되어 백업과 초기화 절차가 명확하지 않음. -> 제안: '백업 절차', '초기화(삭제) 절차', '복원 절차', '레시피 JSON 백업/이전'으로 하위 섹션을 나누고 각 단계에 번호를 붙인다.
  2. [백업] 문제: 'Master 종료 후' 전제조건만 있고, 실행 중 백업 시 파일 잠금 오류 가능성이나 백업 완료 후 확인 항목이 없음. -> 제안: Master 종료 확인 방법과 백업 파일 크기·수정 날짜 확인 단계를 추가한다.
  3. [초기화] 문제: data.db 삭제 후 재생성만 언급되고, 삭제 직전 이중 백본 권고, 재기동 후 정상 생성 여부 확인, 삭제 시 소실되는 이력 범위 안내가 없음. -> 제안: '반드시 별도 경로에 이중 백업' 경고와 재기동 후 data.db 재생성 확인 단계를 추가한다.
  4. [용어] 문제: '카메라 시리얼/디바이스'가 구체적으로 무엇을 의미하는지 불분명함. -> 제안: '카메라 시리얼 번호 및 디바이스 식별 정보' 등으로 구체화하거나, DB에 저장되는 항목을 표로 정리한다.
  5. [레시피 JSON] 문제: 'recipe 폴더'의 정확한 경로(%LOCALAPPDATA%인지 실행 폴더인지)가 없어 실제 백업·복사가 어려움. -> 제안: recipe 폴더의 기본 경로를 명시하고, 레시피만 이전할 때의 주의사항(버전 호환성 등)을 추가한다.

  ## 누락/추가 제안
  - 복원 절차: 백업본을 data.db로 교체하는 구체적인 단계(Master 종료 → 기존 파일 이름 변경 또는 삭제 → 백업 파일 복사 → Master 기동 → 정상 동작 확인).
  - 저장 항목 상세 설명: 촬영 이력, 챔버 이력, 알람 이력, 대시보드 레이아웃 등 각 항목이 DB에서 어떤 의미를 갖는지 간단히 설명.
  - DB 손상/장애 시 대응: LiteDB 파일이 손상되었을 때의 증상과 초기화를 통한 복구 방법.
  - 다중 사용자/PC 이전 시 주의: %LOCALAPPDATA%가 사용자 계정별로 다르므로 다른 PC로 이전할 때 경로 및 파일 권한 확인 필요.
  - 백업 자동화 안내(선택): Windows 작업 스케줄러나 스크립트를 이용한 주기적 백업 예시.

  ## 이미지 자리 검토
  - 이미지 자리 없음. 백업/초기화/복원 절차를 추가할 경우, Explorer 경로 예시, PowerShell 콘솔 실행 화면, data.db 파일 속성 등을 보여주는 그림 1~2개가 유용할 것임.

  ## (선택) 수정 제안 전문
  생략 — 항목별 수정으로 충분함.
