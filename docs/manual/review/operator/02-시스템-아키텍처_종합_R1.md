# 02-시스템-아키텍처 — 검토 종합 (Round 1)

## 판정

수정 필요(중). 현재 내용은 핵심 구조와 주요 토픽은 맞지만, 운영자·유지보수 문서로서는 실제 통신 범위와 실행 관계 설명이 부족하다.

## 합의·다수 수정 (코드 확인됨)

- NATS 표가 핵심 8개 토픽만 다룬다는 점을 명시하고, 누락된 `agent.live.*`, Agent 설정 get/set·snapshot·ack, serial ack, camera ack, Manager 로그 alert/request/dump 토픽을 추가하거나 별도 참조로 연결한다.
- 각 토픽에 실제 예시와 동작 방식(명령, 이벤트, 요청·응답, 주기 발행)을 추가한다. `agent.status.*`의 기본 주기는 설정값 5초이다.
- `agent.result.capture.*`는 `IsSuccess`, Agent 측 `ImagePath`, `ImageBytes`를 전달한다. Master는 수신 바이트를 로컬 캐시에 다시 저장할 수 있으므로 두 경로의 기준 시스템을 구분한다.
- AgentId 규칙을 분리해 설명한다: 수동 방식은 `Agent_{CameraIndex}`, Manager 방식은 `{PCId}_{SHA256(HardwareId)의 앞 8자리 소문자 16진수}`이다. `CameraAlias` 조회가 실패하거나 AgentId가 없으면 `Agent_{CameraIndex}`로 대체된다.
- `Manager`는 별도 구성요소가 아니라 `AgentManager`의 약칭임을 명시하고 용어를 통일한다.
- AgentManager 방식에서는 하나의 AgentUI가 같은 카메라 PC의 여러 카메라를 소유하고, AgentManager가 NATS `runtimeLoad/runtimeUnload` 명령과 하트비트로 감독한다. AgentManager가 카메라마다 Agent 프로세스를 직접 실행하는 구조로 설명하면 안 된다.
- 구성도에는 Master–PLC(XGT FEnet TCP 2004), Master–NATS–AgentUI/AgentManager, 카메라·시리얼 장치의 연결 방향을 표시한다.
- 표의 타겟과 배포 RID를 분리해 표기한다. AgentManager는 `net8.0` 타겟이며 `win-x64` RuntimeIdentifier를 사용한다.

## AI 지적이 부정확 (코드검증)

- AgentManager를 `.NET 8-windows (win-x64)`로 통일하자는 제안은 부정확하다. 실제 TargetFramework는 `net8.0`이고 `win-x64`는 별도 RID이다.
- 캡처 이미지 크기나 예상 대역폭 수치를 추가하자는 제안은 코드만으로 확정할 수 없다. 이미지 바이트 포함과 실시간 프리뷰의 약 100ms 발행 루프는 확인되지만 실제 크기·대역폭은 해상도와 압축 결과에 따라 달라진다.

## 보류 (설비 안전/도메인 확인 필요)

- Master, NATS 서버, AgentManager, AgentUI의 실제 설치 PC와 필수·선택 여부.
- NATS·PLC 포트의 방화벽 개방 범위와 현장 네트워크 배치.
- 하트비트 단절·NATS 재연결 중 운영 화면의 판정 및 안전 대응 절차.
