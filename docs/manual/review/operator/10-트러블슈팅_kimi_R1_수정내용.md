• # 10-트러블슈팅 — kimi 검토 (Round 1)

  ## 종합 평가
  - 수정 필요도: 상
  - 한 줄 요약: 증상-점검 표만 나열했을 뿐 절차, 안전 주의, 로그 위치, 사전 배경 설명이 빠져 있어 설치·설정·유지보수 관리자가 실제로 따라하기 어려운 챕터입니다.

  ## 수정 필요 항목
  1. [전체 구조] 문제: 챕터가 표 한 개(9행)로 끝나며, "어떤 순서로 점검하는가"에 대한 절차나 우선순위가 없습니다. -> 제안: 트러블슈팅의 기본 흐름(증상 확인 → 로그 수집 → 단계별 점검 → 조치/보고)을 안내하는 서론과, 각 항목별 절차 서술 형식(원인→확인 방법→조치→확인)으로 재구성합니다.

  2. ["Agent 초록 점 안 뜸"] 문제: '초록 점'이 Master UI의 어떤 화면(상태 표시등? Devices 목록?)인지 명시되지 않았습니다. -> 제안: "Master 메인 화면 좌측 Devices 패널의 상태 아이콘" 등 구체적인 UI 위치를 언급하거나, 그림을 추가합니다.

  3. ["캡처 타임아웃" / "캡처 실패"] 문제: `frame.Empty()`는 OpenCV 내부 판단 용어로, 관리자 매뉴얼 독자가 이해하기 어렵습니다. -> 제안: "Agent 콘솔에서 'Frame is empty' 또는 유사 메시지가 출력되는지 확인"처럼 로그 메시지 중심으로 풀어 씁니다.

  4. ["값이 이상한 숫자"] 문제: "온도는 ÷10 스케일"이라는 표현이 모호합니다. 어떤 PLC 디바이스의 값인지, PlcSettings의 Scale 설정과의 관계가 불분명합니다. -> 제안: "온도값은 PLC raw word에 10을 곱한 fixed-point 형식(예: 250 → 25.0 °C)으로 표시될 수 있으므로, PlcSettings의 온도 채널 스케일을 확인" 등으로 구체화합니다.

  5. ["셔터 미응답"] 문제: `_openBuffer`/`_closeBuffer`는 코드 내부 변수명입니다. 점검 항목에서 직접 바이트 배열 `{0x04, 0x00, 0x01, ...}`를 언급하지 않고, "Agent가 셔터 열기/닫기 명령을 실제로 COM 포트로 전송하는지(로그 또는 시리얼 모니터로 확인)" 등의 절차를 제시해야 합니다. -> 제안: 관리자가 확인할 수 있는 항목(실제 COM 포트 번호, 포트 점유 여부, Agent 로그) 중심으로 재작성하고, 프로토콜 세부 내용은 개발자용 부록으로 이동합니다.

  6. ["레시피 '챔버 안정화' 멈춤"] 문제: "Tolerance"라는 용어가 Recipe 설정의 어떤 필드인지, 기본값/단위가 무엇인지 제시되지 않았습니다. -> 제안: "Recipe.TemperatureTolerance(기본값 ±1.0 °C) 이내에서 60초 이상 유지해야 다음 스텝으로 진행"처럼 필드명과 단위를 명시합니다.

  7. ["data.db 열 수 없음"] 문제: `*.db-log`는 LiteDB 복구 메커니즘 설명이 부족하고, "자동 복구"라는 표현은 사용자가 기다리기만 하면 되는 것처럼 오해할 수 있습니다. -> 제안: LiteDB 복구 파일(`.db-log`)이 있으면 Master를 한 번 정상 종료시켜 복구를 유도하거나, 백업 후 `db` 파일을 재생성하는 절차를 구체적으로 안내합니다.

  8. [표 전반] 문제: "점검" 칼럼에 여러 후보를 쉼표로 나열하여 우선순위가 불분명합니다. -> 제안: 각 항목을 번호 있는 하위 단계(1. … 2. … 3. …)로 나누어 체계적으로 확인하도록 합니다.

  ## 누락/추가 제안
  - 없음 (없음)
  - 안전 주의사항 누락: 전원/히터/고온 부품 점검 시 감전 및 화상 위험, PLC 통신 중 출력 강제 쓰기 시 기계 동작 위험 등에 대한 경고가 필요합니다.
  - 로그 파일 위치 안내: `%LOCALAPPDATA%\HeatingCameraSystem\logs`, `<Agent exe 폴더>\logs\{AgentId}` 등 실제 로그 경로를 명시해야 합니다.
  - 시뮬레이션/운영 모드 구분: SimulationMode일 때 spawn되지 않는다는 점은 언급되었으나, "시뮬레이션 모드에서만 발생하는 증상"을 별도 구분하면 관리자가 빠르게 원인을 좁힐 수 있습니다.
  - 연락/보고 템플릿: 조치 후에도 해결되지 않을 경우 수집해야 할 정보(로그 파일, 설정 파일, 증상 재현 절차)를 정리한 양식이 있으면 좋습니다.
  - NATS 서버 자체 다운 상황: "Agent 초록 점 안 뜸" 항목은 Agent/NATS URL 위주지만, NATS 서버 프로세스가 실행 중인지(`nats-server`), 방화벽 4222 포트 개방 여부 등을 별도 행으로 추가합니다.
  - Master 중복 실행 검출 방법: "data.db 열 수 없음" 외에도 중복 실행 시 나타나는 구체적인 메시지나 UI 동작을 언급하면 진단이 쉬워집니다.

  ## 이미지 자리 검토
  - [그림 1] 부적절 — 현재 챕터에 이미지 자리가 없습니다. 트러블슈팅은 UI 위치(초록 점, Devices 패널, 레시피 상태)를 보여주어야 효과적인데 시각 자료가 전혀 없어, 독자가 설명대로 따라가기 어렵습니다. Master의 Devices 패널 상태 아이콘과 Agent 콘솔 로그 예시, NATS 연결 오류 메시지 등에 대한 스크린샷 자리를 추가하는 것을 권장합니다.
