# 10-트러블슈팅 — claude 검토 (Round 1)

## 종합 평가
- 수정 필요도: 중
- 한 줄 요약: 증상-점검 표 자체는 실용적이나, 열 구분(점검 vs 조치)이 불명확하고 구현 내부 변수명 노출·경로 불완전·일반 문의 절차 부재가 있음.

## 수정 필요 항목
1. [셔터 미응답 행] 문제: `_openBuffer`/`_closeBuffer`는 코드 내부 변수명으로 보임. 운영/유지보수 관리자 대상 매뉴얼에 소스 레벨 식별자를 그대로 노출하는 건 부적절 -> 제안: "개방/폐쇄 명령 프로토콜(펌웨어 응답 프레임)" 등 사용자 관점 용어로 교체하거나, 실제 확인 방법(로그에서 어떤 문자열을 보면 되는지)으로 대체.
2. [PLC 온습도 0 고정 행] 문제: `hardware.json`의 전체 경로가 없어 관리자가 파일을 못 찾을 수 있음 -> 제안: 절대경로 또는 이전 챕터(설치/설정) 참조 번호 추가.
3. [승인했는데 Agent 안 뜸 행] 문제: `logs\{AgentId}` 경로가 상대경로만 표기되어 루트 위치 불명 -> 제안: 전체 경로 명시 또는 "§ 로그 위치" 챕터 참조 추가.
4. [레시피 '챔버 안정화' 멈춤 행] 문제: "STOP 후 점검"이라 되어 있는데, 자동 정지인지 수동 STOP이 필요한지 불명확 -> 제안: "자동으로 대기 상태 유지되며, 관리자가 수동으로 STOP해야 함" 등 주체를 명시.
5. [표 헤더 전반] 문제: '점검' 열에 원인 설명과 조치 방법이 혼재되어 있어 가독성 낮음 -> 제안: '증상 | 원인 | 확인/조치'로 열 분리 검토.

## 누락/추가 제안
- 표로 해결 안 될 때 절차(로그 수집 방법, 문의처)가 없음. 마지막에 "위 항목으로 해결 안 되면 Agent/Master 로그 폴더를 첨부해 담당자에게 문의" 같은 안내 한 줄 추가 제안.
- "Devices에 카메라 안 뜸" 행의 `manager-state.json` 엔트리 관련, 엔트리를 어떻게 확인/수정하는지 방법 누락 — 단순 존재 확인만으로는 조치 불가.
- 각 증상별 우선순위/심각도 구분(예: 운영 중단 vs 경미) 없음. 다수 증상이 섞여 있어 급한 것부터 봐야 하는지 안내 필요.

## 이미지 자리 검토
- 이미지 자리(📷 [그림 N]) 없음 — 해당 없음. 다만 Agent 콘솔 로그 화면, `manager-state.json` 예시 등 스크린샷이 있으면 진단 속도에 도움될 것으로 판단됨(완결성 관점 제안).
