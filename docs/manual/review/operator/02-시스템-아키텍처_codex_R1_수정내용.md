# 02-시스템-아키텍처 — codex 검토 (Round 1)

## 종합 평가
- 수정 필요도: 중
- 한 줄 요약: 구성요소와 메시지 흐름은 간결하지만, 설치·유지보수에 필요한 배치 관계와 식별자 규칙 설명이 부족하고 일부 명칭이 일관되지 않는다.

## 수정 필요 항목
1. [2.1 구성 / AgentManager] 문제: 역할에는 `Agent 승인·감독`이라고 되어 있으나 그림과 NATS 토픽에서는 `Manager`로 축약되어 별도 구성요소처럼 보인다. -> 제안: 본문 전체에서 `AgentManager`로 통일하고, 토픽 방향도 `AgentManager→Master`처럼 표기한다.
2. [2.1 구성 / AgentManager 타겟] 문제: `.NET 8(win-x64)`는 프레임워크와 배포 RID가 혼합된 표기여서 다른 행의 타겟 표기와 기준이 다르다. -> 제안: 타겟은 `.NET 8`로 쓰고, 별도 비고 열에서 `win-x64 배포`라고 명시한다.
3. [2.1 구성] 문제: 설치 관리자가 알아야 할 각 구성요소의 실행 위치와 필수·선택 여부가 없다. 특히 NATS 서버가 표에 없고 Master, AgentManager, Agent 간 배치 관계를 파악하기 어렵다. -> 제안: `설치 위치`와 `필수 여부` 열을 추가하고 NATS 서버를 독립 구성요소로 포함한다.
4. [2.1 구성 / Protocols] 문제: `VagabondK`, `NATS.Net`, `Fake`, `AppServices 정적 서비스 로케이터` 등 개발 구현 세부가 중심이어서 대상 독자에게 필요한 운영 정보가 약하다. -> 제안: 본문에서는 “PLC·메시징·시리얼·카메라 통신 구현”처럼 역할 중심으로 설명하고 라이브러리명과 Fake 구현은 개발 문서로 분리한다.
5. [2.2 NATS 토픽] 문제: `{AgentId}`, `{PCId}`가 자리표시자라는 설명과 실제 토픽 예시가 없어 설정 및 장애 분석 시 혼동할 수 있다. -> 제안: 중괄호 항목을 실제 식별자로 치환한다는 설명과 토픽 예시를 각각 1개 이상 추가한다.
6. [2.2 NATS 토픽 / 식별자 설명] 문제: `HardwareId해시8`, `CameraAlias`, `DB조회`, `폴백`의 생성·등록 주체와 실패 시 결과가 설명되지 않는다. -> 제안: `HardwareId 해시 앞 8자리`처럼 형식을 명확히 정의하고, Alias 등록 위치와 조회 실패 시 `Agent_{CameraIndex}`가 사용되는 조건을 구체적으로 적는다.
7. [2.2 NATS 토픽 / agent.result.capture] 문제: `성공여부`는 띄어쓰기가 빠졌고 `경로`가 Master 기준인지 Agent 로컬 경로인지 불명확하다. -> 제안: `성공 여부`로 고치고 경로의 기준 시스템을 명시한다.
8. [2.2 NATS 토픽 / server.cmd.mgr] 문제: 다른 관리 토픽은 `agent-mgr` 접두사를 사용하지만 명령 토픽은 `server`를 사용해 명명 규칙이 달라 보인다. -> 제안: 실제 구현 명칭이라면 변경하지 말고, 호환성 때문에 사용하는 고정 토픽임을 설명한다.

## 누락/추가 제안
- Master, NATS 서버, Agent/AgentUI, AgentManager, PLC, 시리얼 셔터 사이의 연결 방향과 프로토콜을 한눈에 보여 주는 논리 구성도를 추가한다.
- 설치·방화벽 설정에 직접 필요한 NATS 및 PLC 연결 주소·포트는 해당 설정 절을 참조하도록 안내한다.
- `Agent`와 `AgentUI`의 관계, 동일 PC에서 함께 실행되는지 여부를 명시한다.
- AgentManager 방식과 수동 Agent 방식의 적용 조건을 짧게 비교한다.
- 하트비트가 끊기거나 NATS가 재연결 중일 때 Master에 표시되는 상태와 기본 판정 기준은 운영 또는 장애 대응 절을 참조하도록 연결한다.

## 이미지 자리 검토
- [그림 1] 부적절 — 위치와 주제는 적절하지만 “실제 배치도 또는 현장 배치 사진”만으로는 논리 연결, 프로토콜, 통신 방향을 설명하기 어렵다. 현장 사진보다 Master·NATS·AgentManager·Agent·PLC·챔버를 연결하고 방향 및 포트를 표시한 네트워크 아키텍처 다이어그램을 우선 사용해야 한다.
