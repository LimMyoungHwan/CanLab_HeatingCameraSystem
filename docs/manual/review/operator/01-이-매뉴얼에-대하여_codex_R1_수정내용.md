# 01-이-매뉴얼에-대하여 — codex 검토 (Round 1)

## 종합 평가
- 수정 필요도: 중
- 한 줄 요약: 대상 독자와 범위는 명확하지만, 참조 문서 연결과 임시 PLC 주소 확인 절차를 관리자 관점에서 구체화해야 한다.

## 수정 필요 항목
1. [첫 문단] 문제: `[사용자 매뉴얼]`이 링크나 정확한 문서명 없이 표기되어 참조 위치를 알 수 없다. -> 제안: 실제 파일 또는 문서 경로를 연결하고, 링크를 제공할 수 없다면 정확한 문서명을 기재한다.
2. [다루는 내용] 문제: `설정 파일(hardware.json/agent.json/manager)`에서 `manager`가 파일명인지 설정 영역인지 불명확하며 다른 두 항목과 표기 수준이 일치하지 않는다. -> 제안: 실제 파일명이면 확장자를 포함한 정확한 이름으로, 설정 영역이면 `Agent Manager 설정`처럼 구분해 표기한다.
3. [[주의] 문구] 문제: 관리자가 확인해야 할 위치로 `소스 주석의 ponytail 표시`를 안내하지만, 운영 문서 독자가 소스 코드를 열어야 하는지와 해당 표시의 의미가 설명되지 않는다. 또한 프로젝트의 알려진 임시값 전체가 반드시 `ponytail`로 표시되어 있다고 단정하기 어렵다. -> 제안: 임시값은 본 매뉴얼의 관련 표와 실제 PLC 명세를 기준으로 확인하도록 안내하고, 소스 확인이 필수 절차가 아니라면 해당 문구를 삭제한다.
4. [[주의] 문구] 문제: 임시 PLC 주소 교체 전 백업과 변경 후 검증 절차가 없다. 잘못된 주소는 설비 오동작으로 이어질 수 있다. -> 제안: `hardware.json 백업 → 전원 차단 또는 안전 상태 확인 → 주소 변경 → 시뮬레이션/수동 점검 → 재시작 후 상태 확인`의 원칙을 관련 설정 장으로 연결한다.

## 누락/추가 제안
- 매뉴얼에서 사용하는 경로, 파일명, 화면 명칭은 실제 설치 버전과 다를 수 있으므로 적용 대상 소프트웨어 버전 또는 문서 개정 정보를 명시하는 것이 좋다.
- `PLC 주소 조정`, `카메라 승인`, `백업`, `장애 대응` 등 고위험 작업은 해당 장의 안전 주의사항과 사전 조건을 반드시 확인하도록 짧은 안내를 추가하는 것이 좋다.
- 약어가 처음 등장하는 `PLC`, `NATS`, `LiteDB`는 대상 독자의 이해 수준을 고려해 용어집이나 관련 장으로 연결하는 것이 좋다.

- 이미지 자리 없음 — 문서의 목적과 범위를 소개하는 장이므로 별도 그림은 필요하지 않다.
