# 09-LiteDB(data.db)-관리 — claude 검토 (Round 1)

## 종합 평가
- 수정 필요도: 중
- 한 줄 요약: 경로·데이터 항목 설명은 코드와 일치해 정확하나, 백업 파일 복원 절차와 실행 중 조작 시 위험 경고가 빠져 있어 관리자가 사고를 낼 여지가 있다.

## 수정 필요 항목
1. [백업 항목] 문제: "Master 종료 후" 조건만 명시하고 이유(실행 중 복사 시 파일 잠금으로 실패하거나 불완전한 스냅샷이 복사될 수 있음)를 설명하지 않아, 관리자가 왜 종료해야 하는지 모른 채 임의로 실행 중 복사를 시도할 위험 있음 -> 제안: "Master 실행 중에는 data.db가 잠겨 있어 복사가 실패하거나 손상된 사본이 만들어질 수 있음"과 같은 근거 문구 추가.
2. [백업 항목] 문제: 백업 방법만 있고 복원(restore) 절차가 전혀 없음 -> 제안: "복구: Master 종료 → 백업 .db 파일을 data.db로 덮어쓰기 → Master 재시작" 절차 추가.
3. [초기화 항목] 문제: 초기화 시 사라지는 데이터(촬영/챔버/알람 이력, 대시보드 레이아웃, 카메라 시리얼·디바이스 등록 정보)가 모두 사라진다는 영향 범위 설명이 없어, "빈 DB 재생성"만 보고 가볍게 여길 수 있음 -> 제안: "초기화 시 이력·대시보드 레이아웃·카메라 등록 정보가 모두 삭제되며 레시피는 별도 폴더라 영향 없음"을 명시.
4. [전체] 문제: 다른 챕터(10-트러블슈팅)에는 `data.db-log`(WAL) 파일과 강제 종료 시 자동 복구 동작이 언급되는데, 본 챕터에는 없어 일관성이 떨어짐 -> 제안: data.db 옆에 생기는 `-log` 파일 존재와 "삭제/백업 시 함께 처리" 안내를 짧게 추가하거나 10장을 상호 참조.

## 누락/추가 제안
- 백업 스크립트가 PowerShell만 제공됨. 관리자가 GUI 환경만 다룰 수도 있으므로 탐색기에서 파일 직접 복사하는 방법도 한 줄 병기하면 좋음.
- 정기 백업 주기(예: 일/주 단위 권장)에 대한 안내가 없음. 운영 관리자 대상 챕터이므로 최소 권장 주기 한 줄 추가 고려.

## 이미지 자리 검토
- 없음 — 이 챕터에는 📷 [그림 N] 자리가 전혀 없음. data.db 파일 위치(탐색기에서 %LOCALAPPDATA%\HeatingCameraSystem 폴더) 스크린샷 1개는 관리자가 경로를 직접 찾는 데 도움이 되므로 추가를 권장.
