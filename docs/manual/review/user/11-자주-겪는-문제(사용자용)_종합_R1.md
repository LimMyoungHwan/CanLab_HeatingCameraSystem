# 11-자주-겪는-문제(사용자용) — 검토 종합 (Round 1)

## 판정

수정 필요. 증상별 절차와 문의 기준을 명확히 하되, 코드에 없는 조작·안전 절차는 추가하지 않는다.

## 합의·다수 수정 (코드 확인됨)

- 각 항목을 `상태 확인 → 사용자 조치 → 운영자 문의` 순서로 통일한다.
- 카메라는 기본 5초마다 하트비트를 보내며 Master는 15초 무응답 시 오프라인 처리한다. “잠시 후” 대신 이 기준을 명시한다.
- 캡처 타임아웃 시 대상 Agent의 온라인 상태와 카메라 매핑을 확인하도록 구체화한다.
- PLC 연결 표시가 비정상이면 연결 문제로, 연결은 정상이나 온도·습도가 계속 0이면 설비 담당자 문의로 구분한다.
- “챔버 안정화”는 코드상 현재 온도가 목표 온도 허용범위에 들어올 때까지 대기하는 단계다. 사용자 직접 설비 점검 대신 STOP 후 운영자 문의로 정리한다.
- 알람 필터는 표시만 거르며 원인을 해소하지 않는다. `BuzzerOffCommand`와 `ResetErrorCommand`는 별도 PLC 명령이므로, 원인 확인 없이 리셋하면 해결된다는 표현을 제거한다.
- RECIPE 목록에는 실제 `RefreshRecipesCommand`가 있으므로 “목록이 비어 있으면 새로고침” 항목 추가가 가능하다.
- 문의 시 발생 시각, 대상 Agent/카메라, 알람 메시지, PLC·Agent 연결 상태를 전달하도록 안내한다.

## AI 지적이 부정확 (코드검증)

- “레시피 카메라 번호와 Agent PC 번호가 반드시 일치”한다는 지적은 절대 규칙이 아니다. `CameraAlias` 등록이 있으면 해당 `AgentId`를 우선 사용하고, 없을 때만 `Agent_{CameraIndex}`로 대체한다.
- 챔버 안정화를 “목표 온도 또는 습도 미도달”로 설명하면 부정확하다. 현재 대기 조건은 온도만 검사한다.
- 캡처 타임아웃 후 자동 STOP·재시도를 지시하는 제안은 구현과 다르다. 엔진은 경고를 기록한 뒤 다음 스텝으로 진행한다.
- “하단 알람 배너/알람 탭” 등 고정 위치 제안은 현재 UI 구조와 일치하지 않는다. 실제 화면 명칭과 위치를 다시 확인해 표기해야 한다.

## 보류 (설비 안전/도메인 확인 필요)

- 비상정지 배너 발생 시 해제 절차와 재가동 조건.
- 챔버 안정화 실패 시 운전자가 수행할 수 있는 설비 점검 범위.
- 부저 OFF와 에러 리셋의 허용 순서 및 권한.
- 캡처 타임아웃 시 STOP 여부와 재시도 정책.
- 상태 표시와 버튼 위치를 보여 주는 화면 이미지 추가.
