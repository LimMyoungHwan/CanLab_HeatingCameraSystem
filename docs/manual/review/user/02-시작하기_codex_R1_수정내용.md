# 02-시작하기 — codex 검토 (Round 1)

## 종합 평가
- 수정 필요도: 중
- 한줄 요약: 시작 절차와 화면 구성을 이해하기 쉽지만, 정상 운전 판단 기준과 위험도가 높은 공용 제어 버튼의 사용 조건·복구 절차가 부족하다.

## 수정 필요 항목
1. [2.1 프로그램 실행과 첫 화면] 문제: 실행 직후 NATS·PLC 연결을 시도한다고 설명하지만, 사용자가 촬영을 시작해도 되는 상태를 판단하는 방법이 없다. → 제안: PLC 연결 표시, Agent 상태, 비상정지 상태 및 활성 오류 알람을 확인한 뒤 운전을 시작하도록 안내한다.
2. [2.1 프로그램 실행과 첫 화면] 문제: “연결에 실패해도 화면은 정상적으로 열림”만으로는 실패 상태에서 가능한 작업과 금지되는 작업을 알 수 없다. → 제안: PLC 또는 Agent가 연결되지 않은 상태에서는 자동 운전·수동 조작·촬영을 시작하지 말고, 연결 상태와 알람을 먼저 확인하도록 경고를 추가한다.
3. [2.2 화면 구성 — 좌측 메뉴] 문제: `Agent 설정`의 “원격 설정(구) / 카메라 승인·관리(신)” 표기는 임시 편집 메모처럼 보이며 실제 사용 화면을 특정하지 못한다. → 제안: 현재 배포 버전에 표시되는 정식 메뉴명과 기능만 기재한다.
4. [2.2 화면 구성 — 좌측 메뉴] 문제: `PLC 설정`에 연결 설정과 관리자용 서보 좌표 설정이 함께 소개되지만, 일반 운전자가 변경해도 되는 항목인지 구분되지 않는다. → 제안: 관리자 전용 화면임을 명시하고, 승인 없이 PLC 주소·서보 좌표를 변경하지 말라는 경고를 추가한다.
5. [2.2 공용 버튼] 문제: `PLC 부저 OFF`, `PLC 오류 리셋`, `PLC 원점 복귀`를 “자주 쓰이는 PLC 즉시 명령”으로만 설명한다. 특히 오류 리셋과 원점 복귀의 실행 조건, 설비 동작 가능성, 작업자 안전 확인 절차가 없다. → 제안: 각 버튼의 용도와 실행 전 확인 사항을 구분하고, 원점 복귀 전 챔버 내부 작업자·장애물 유무와 비상정지 해제 여부를 확인하도록 경고한다.
6. [2.2 공용 버튼] 문제: `PLC 오류 리셋`이 오류 원인을 제거하지 않은 상태에서도 사용할 수 있는 것으로 읽힌다. → 제안: 알람 원인을 확인하고 원인을 제거한 뒤 리셋하며, 반복 발생 시 관리자에게 연락하도록 안내한다.
7. [2.2 공용 버튼] 문제: `비상정지` 버튼을 누른 뒤 설비에 어떤 영향이 있는지와 정상 복귀 절차가 없다. → 제안: 정지 대상과 해제 방법을 실제 시스템 동작에 맞게 설명하고, 원인 확인 없이 운전을 재개하지 않도록 경고한다.
8. [2.2 알람 영역] 문제: 알람의 긴급도 필터와 개별 해제는 설명하지만, “해제”가 원인 제거·PLC 오류 리셋·목록 확인 처리 중 무엇을 의미하는지 불명확하다. → 제안: 해제 버튼의 실제 효과를 명시하고, 화면에서 알람을 지워도 설비 오류 원인이 자동으로 해결되는 것은 아닌지 분명히 한다.
9. [2.3 정상 상태 확인] 문제: PLC 표시등 위치가 “좌측 하단(또는 상단)”으로 적혀 있어 실제 화면 위치를 특정하지 못한다. → 제안: 현재 화면 기준의 정확한 위치로 통일한다.
10. [2.3 정상 상태 확인] 문제: 정상 상태 확인 항목이 PLC와 Agent에 한정되어 있으며 활성 오류 알람과 비상정지 상태 확인이 빠져 있다. → 제안: “PLC 연결 초록색, 필요한 Agent 모두 초록색, 오류·경고 알람 없음, 비상정지 해제”를 운전 시작 전 체크리스트로 제시한다.
11. [2.3 정상 상태 확인] 문제: Agent가 5초 이내 하트비트를 보내면 준비 완료라고 단정하지만, 하트비트 수신은 통신 상태만 나타낼 수 있으며 실제 카메라 촬영 준비 상태와 동일한지 본문만으로 확인할 수 없다. → 제안: 초록색 표시의 정확한 의미를 “Agent 통신 정상” 또는 실제 구현에 맞는 상태명으로 수정한다.
12. [2.3 정상 상태 확인] 문제: 회색 표시와 “응답 없음(15초 이상)” 이후 운전자가 수행할 점검 순서가 없다. → 제안: 해당 Agent PC 전원, Agent 프로그램 실행 여부, 카메라 연결, 네트워크 및 NATS 연결을 순서대로 확인하도록 안내한다.

## 누락/추가 제안
- 프로그램 실행 전 PLC·카메라 Agent PC·NATS 서버가 켜져 있어야 하는지 등 필수 사전 조건을 추가한다.
- 프로그램 종료 방법과 종료 전 자동 운전 중지 여부를 간단히 안내한다.
- 최초 실행과 일상 실행을 구분하고, 최초 실행 시 관리자 설정이 필요한 경우 해당 장을 참조하도록 연결한다.
- 정상 상태 확인 절차를 번호가 있는 체크리스트로 구성하면 일상 운전자가 빠르게 점검할 수 있다.
- 연결 실패가 지속될 때 참조할 문제 해결 장 또는 관리자 연락 기준을 추가한다.

## 이미지 자리 검토
- [그림 2] 적절 — 첫 실행 직후의 전체 화면과 기본 진입 화면을 보여 주므로 프로그램이 정상적으로 열린 상태를 확인하는 데 유용하다. PLC 연결 표시와 Agent 상태 표시가 식별되도록 캡처 설명을 보완하면 좋다.
- [그림 3] 대체로 적절 — 좌측 메뉴, 공용 버튼, 알람 목록, 비상정지의 위치를 한 번에 설명할 수 있다. 다만 알람 1건 이상을 표시할 경우 예시 알람임을 명시하고, 위험 버튼과 연결 표시가 잘 보이도록 주석 또는 번호 표기를 추가하는 편이 좋다.
