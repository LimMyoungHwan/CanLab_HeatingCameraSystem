• # 04-레시피-만들기·실행 — kimi 검토 (Round 1)

  ## 종합 평가
  - 수정 필요도: 중
  - 한 줄 요약: 절차와 단계 흐름은 실제 구현(RecipeEngine, RecipeEditorView)과 대체로 일치하나, 실행 중 실패/중단 동작·화면에 보이지만 설명 없는 요소(CAPTURE MODE, NODE ASSIGNMENT, 복사/삭제)에 대한 보완이 필요함.

  ## 수정 필요 항목
  1. [4.2 항목 1] 문제: 레시피 목록 하단에 '새 레시피' 외에 복사(Recipe_CopyRecipe), 삭제 버튼이 실제로 있으나 언급이 없음 -> 제안: "복사로 기존 레시피 복제, 삭제로 선택 레시피 제거" 한 줄 추가.
  2. [4.2 항목 2] 문제: Recipe Settings 영역에 CAPTURE MODE(Sequential/Simultaneous) 토글이 화면에 보이나 매뉴얼 설명이 없음(현재 UI상 플레이스홀더) -> 제안: "CAPTURE MODE는 현재 Sequential 고정이며 선택 동작은 미구현"이라는 주의를 달거나, 화면 구성 소개(4.1)에서 언급.
  3. [4.2 항목 4] 문제: 스텝 입력 항목에 NODE ASSIGNMENT 필드가 실제로 존재하나 누락됨 -> 제안: 스텝 항목에 "NODE ASSIGNMENT(스텝 이름/메모용 텍스트)"를 추가 설명. 화면 라벨은 `BLACKBODY REF °C`, `CHAMBER °C`, `CHAMBER %RH`이므로 괄호 표기도 실제 라벨과 맞출 것.
  4. [4.2 항목 4 / 4.5] 문제: 스텝별 챔버 ℃/%RH를 입력받지만, 실제 실행 엔진(RecipeEngine)은 레시피 공통 목표 온도/습도만 사용하고 스텝별 챔버 값은 실행에 반영하지 않음. 운전자가 스텝별 챔버 조건이 개별 적용된다고 오해할 수 있음 -> 제안: "스텝의 챔버 ℃/%RH는 참고용으로 저장되며, 실행 시 챔버 조건은 상단 레시피 공통 설정값으로만 제어된다"는 참고 추가(구현 변경 예정이라면 그에 맞게 수정).
  5. [4.3] 문제: XY TARGET 입력란과 USE CURRENT X/Y가 '선택된 스텝'의 X/Y 필드와 연동된다는 설명이 없음 — 스텝을 선택하지 않으면 동작이 다르게 느껴질 수 있음 -> 제안: "먼저 가운데에서 스텝을 선택하면, XY TARGET 입력란이 그 스텝의 좌표가 되며 USE CURRENT X/Y는 현재 서보 위치를 그 스텝에 바로 기록한다"로 명확화.
  6. [4.3] 문제: 조그 패드는 누르고 있는 동안만 이동(press-and-hold) 방식이나 "미세 이동"만 기술됨 -> 제안: "버튼을 누르고 있는 동안 해당 방향으로 이동하고, 떼면 정지한다"로 구체화.
  7. [4.5 참고] 문제: 타임아웃('경고')·캡처 실패('오류') 발생 시 레시피가 중단되지 않고 다음 스텝으로 계속 진행된다는 사실(실제 구현 동작)이 빠져 있음 — 운전자가 알람 후 전체 실패로 오인 가능 -> 제안: "알람이 떠도 해당 스텝만 건너뛰고 다음 스텝으로 진행된다"는 문장 추가.
  8. [4.5] 문제: 실행 중 중단(STOP) 방법과 진행 상태 표시 위치에 대한 설명이 전혀 없음 -> 제안: 대시보드의 진행 단계 표시(챔버 안정화/서보 이동/BB 안정화/캡처/완료)를 어디서 보는지, 중단 버튼이 있는지(없다면 재실행 시 주의점) 기술.

  ## 누락/추가 제안
  - 실행 전제조건 한 줄: 대상 카메라 Agent가 온라인이어야 하고, 카메라 드롭다운에는 온라인 Agent 카메라만 표시됨 — 오프라인 상태에서 실행 시 캡처 타임아웃 경고가 난다는 점을 4.5 앞에 두면 좋음.
  - 'SAVE RECIPE' 저장 위치: "파일로 저장됨"만 있는데, 어느 폴더/파일인지(EXPORT와의 차이) 간단히 구분해 주면 백업 절차(4.4)와 연결이 매끄러움.
  - 챔버 안정화 대기에도 허용오차가 적용된다는 점(목표 온도 '도달'이 아니라 허용오차 이내 진입)을 표 설명에 반영하면 BB 안정화 행과 표현이 일관됨.
  - 4.4 IMPORT 시 같은 이름 레시피가 있을 때의 동작(덮어쓰기/추가) — 현재 "불러와 추가"만 있어 확인 필요.

  ## 이미지 자리 검토
  - [그림 7] 적절 — 3분할 전체 구성을 첫 소개에서 보여주는 것은 필수. "레시피 1개 선택 상태" 지정도 적절.
  - [그림 8] 적절 — 스텝 입력 항목이 많아(노드/흑체/X·Y/챔버/카메라) 그림 없이는 설명이 어려움. 스텝 2개 이상 + 드래그 핸들(=)과 X 버튼이 보이도록 지시하면 더 좋음.
  - [그림 9] 적절 — 조그 패드·XY TARGET·셔터 버튼 배열은 그림이 필요함. "카메라 영상이 나오는 상태" 조건이 명시되어 좋음. 다만 영상이 검은 화면이면 버튼 라벨이 안 보일 수 있으니, 영상 대신 패널 하단(버튼 영역)이 잘 보이는 구도를 권장.
