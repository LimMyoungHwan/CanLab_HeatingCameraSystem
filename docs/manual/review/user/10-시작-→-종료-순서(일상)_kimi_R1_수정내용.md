• # 10-시작-→-종료-순서(일상) — kimi 검토 (Round 1)

  ## 종합 평가
  - 수정 필요도: 중
  - 한 줄 요약: 절차 순서 자체는 맞지만, 일상 운전자가 판단할 기준(언제·무엇을 확인하는지)과 예외 상황 안내가 거의 없어 실무에서 그대로 쓰기엔 너무 간략함.

  ## 수정 필요 항목
  1. [전체] 문제: 각 단계가 명령문 한 줄이라 확인 기준이 없음. 예: 1번 "NATS 서버가 켜져 있는지 확인" — 무엇으로 확인하는지(서버 PC 상태? Master 연결 표시?)가 없어 운전자가 판단 불가. → 제안: 각 단계에 "확인 방법/정상 기준"을 한 줄씩 추가(예: "Master 대시보드의 NATS 연결 표시가 초록인지 확인").
  2. [3번] 문제: "대시보드에 초록 점 확인(5초 내)" — Agent 하트비트는 5초 간격이므로 기동 직후 5초를 약간 넘길 수 있음. 5초가 지나도 초록이 아니면 오판 유발. → 제안: "(약 5~10초 소요)"로 표기하고, 안 뜰 경우 Agent PC 실행 여부·NATS 연결 상태 확인 안내 한 줄 추가.
  3. [4번] 문제: "(필요 시)"의 판단 기준이 없음 — 언제 설정 전송이 필요한지(최초 1회? 카메라 교체 후? 매일?) 일상 운전자가 알 수 없음. → 제안: "카메라·시리얼 설정을 변경한 경우에만 전송. 설정 변경이 없으면 생략 가능"처럼 기준 명시.
  4. [6번] 문제: 모니터링 중 이상 발생 시 대처가 전혀 없음. 알람이 울리면 어떻게 하는지가 이 챕터의 핵심 공백. → 제안: "알람 발생 시 대시보드의 알람 내역에서 원인 확인 후, 필요하면 해당 챕터(알람/트러블슈팅)로 이동" 식의 연결 안내 추가.
  5. [8번] 문제: 종료 순서가 "카메라 PC 종료 → Master 창 닫기"로 기술되어 있으나, 진행 중인 레시피가 있을 때 종료하면 어떻게 되는지(중단되는지, 경고가 뜨는지) 안내가 없음. → 제안: "진행 중인 레시피가 없는지 확인 후 종료" 단계 추가, 또는 "레시피 진행 중 종료 시 촬영이 중단됨" 경고 한 줄 추가.
  6. [8번] 문제: Master와 카메라 PC의 종료 순서가 왜 이 순서인지/반대로 해도 되는지 불명확. → 제안: 순서가 중요하지 않다면 "(순서 무관)" 명시, 중요하다면 사유 한 줄 추가.

  ## 누락/추가 제안
  - 시작 전 안전/상태 확인 단계: 최소한 "비상정지 해제 상태·챔버 정상 여부 등 시스템 화면의 상태 표시 확인" 한 단계를 4~5번 사이에 넣을 것(일상 운전 챕터의 통상적 필수 항목).
  - 7번 "이력 조회에서 결과 확인" — 실패 결과(캡처 실패 건)를 어떻게 구분해 보는지 한 줄이 있으면 좋음.
  - 하루 운전 루틴의 시작/종료를 표나 체크리스트 형태로 요약해 두면 운전자가 출력해 쓰기 좋음(선택).

  ## 이미지 자리 검토
  - 챕터 내 📷 [그림 N] 자리 없음 — 다음 자리를 추가할 것을 제안:
    - [그림 1] 대시보드 화면(카메라 초록 점 + 레시피 선택 + START 버튼이 한 화면에 보이는 캡처) — 3~5번 단계를 한 그림으로 커버, 일상 운전자에게 가장 유용한 자리.
    - [그림 2] 진행바·알람 표시 화면 — 6번 모니터링 단계 보조(선택).
  - 이외의 단계(1, 7, 8번)는 텍스트만으로 충분하며 억지 이미지 자리는 불필요.
