• # 01-이-매뉴얼에-대하여 — kimi 검토 (Round 1)

  ## 종합 평가
  - 수정 필요도: 하
  - 한 줄 요약: 매뉴얼 목적·대상 독자·범위가 명확하고 시스템 개요도 운전자 눈높이에 맞게 간결하게 정리되어 있어, 소규모 표현 다듬기 수준만으로 충분함.

  ## 수정 필요 항목
  1. [본문 1항] 문제: "별도 [운영자 매뉴얼]을 참조한다"에서 대상 독자가 '운전자'인데 참조 문서명이 '운영자 매뉴얼'이라 두 용어(운전자/운영자)가 혼용됨. 매뉴얼 전체에서 독자 호칭이 흔들릴 위험 있음 -> 제안: 독자 호칭을 "운전자"로 통일하고, 참조 문서명은 실제 문서 제목 그대로(예: 『HeatingCameraSystem 운영자 매뉴얼』) 표기하며, 첫 등장 시 "운영자 매뉴얼(관리자용)"처럼 구분 부연 추가.
  2. [1.1 첫 문장] 문제: "열·습도 챔버 안에 설치된 여러 대의 열화상 카메라" — 챔버가 '열·습도 챔버'인지 '항온항습 챔버'인지 명칭이 임의적이고, "열·습도 챔버"는 일반적 명칭이 아님 -> 제안: 실제 설비 명칭(예: 항온항습 챔버)으로 고치거나, 확정 전까지 "챔버(온도·습도 시험 설비)"로 표현.
  3. [1.1 개요 문장] 문제: "각 지점의 온도·습도와 함께 이미지를 저장하는 시스템"이라 했으나 바로 아래 구성 요소 설명에는 온도·습도를 어디서 읽는지(PLC 등) 언급이 없어, 구성 요소 목록(Master/Agent/NATS)과 개요 문장 사이에 단절감이 있음 -> 제안: "온도·습도는 PLC를 통해 챔버에서 읽어 옴(운전자가 직접 만질 일 없음)" 수준의 한 줄을 추가하거나, 구성 요소에 챔버/PLC를 4번째 항목으로 간략히 추가.
  4. [그림 1 설명] 문제: "운영자 매뉴얼 2장의 구성도를 그대로 써도 됨"은 매뉴얼 작성자용 지시문으로, 완성본에 그대로 남으면 독자에게 노출될 수 있는 메모 성격 문구 -> 제안: 최종 편집 단계에서 삭제할 편집 메모임을 표시하거나(예: `> ※ 편집 메모:`), 지금 단계에서 그림 캡션 확정 시 제거 대상으로 명시.

  ## 누락/추가 제안
  - 1장 말미에 "이 매뉴얼의 구성(각 장 요약)" 3~5줄을 두면 운전자가 필요한 장으로 바로 이동하기 쉬움. 현재 "다루는 내용" 목록이 사실상 그 역할을 하므로 필수는 아니며, 챕터 목차만 간단히 연결해도 충분.
  - "레시피"라는 용어가 설명 없이 등장함. 1.1에서 "(촬영 순서표)"라는 부연은 있으나, 용어집이나 후속 장(레시피 작성 장)으로의 참조 한 줄을 두면 친절함.

  ## 이미지 자리 검토
  - [그림 1] 적절 — 매뉴얼 첫 장의 시스템 개요에 전체 구성도는 필수적이며, 캡처 대상(실제 설비 사진 또는 네트워크 구성도)과 대체 방안(운영자 매뉴얼 구성도 재사용)이 명확히 기술되어 있음. 다만 "운영자 매뉴얼 2장 구성도 재사용" 지시는 최종본에서 제거 필요(위 수정 항목 4 참조).
