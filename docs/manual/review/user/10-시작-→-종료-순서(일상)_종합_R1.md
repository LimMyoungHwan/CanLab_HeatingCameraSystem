# 10-시작-→-종료-순서(일상) — 검토 종합 (Round 1)

## 판정

수정 필요도: **상**. 시작 조건, Agent 실행, 설정 전송 조건, 완료·종료 판단을 보완해야 한다. 단, 코드에 없는 NATS 표시·카메라 Ready·종료 순서의 안전 효과는 문서에 단정하지 않는다.

## 합의·다수 수정 (코드 확인됨)

- “카메라 PC 기동”을 **Agent 또는 AgentUI 프로그램 실행 후 연결 확인**으로 수정한다.
- 하트비트 기본 주기는 5초지만 수신 시점은 보장되지 않으며, Master는 마지막 하트비트가 15초를 넘으면 오프라인으로 판정한다. “5초 내” 단정 대신 **온라인 표시 확인 후 진행**으로 쓴다.
- Agent 설정 전송은 일상 필수 절차가 아니다. 설정 조회 후 값을 편집·전송하고 ACK로 성공 여부를 확인하는 기능이므로 **설정 변경 시에만 수행**하도록 분리한다.
- START 직전에 선택한 레시피와 PLC·필요 Agent 상태를 확인하도록 보완한다. 현재 START 명령은 레시피 선택과 복구 잠금만 검사하며, PLC·NATS·Agent 연결을 모두 선행 조건으로 강제하지 않는다.
- 운전 중 진행률·현재 단계·알람 수를 확인하도록 명시한다.
- 완료 판단은 대시보드의 `완료` 상태이며, 성공한 촬영만 이력에 저장된다. 완료 후 이력 조회에서 촬영 결과를 확인하도록 구체화한다.
- 종료 전에 레시피가 `완료` 또는 `중지됨`인지 확인하도록 보완한다. Master 창 닫기는 실행 중 레시피의 STOP 명령을 자동 호출하지 않는다.
- 실제 UI에 존재하는 **PLC 상태, Agent 온라인 수, 레시피 선택·START/STOP, 진행률·알람, 이력 조회** 화면의 그림 자리를 추가한다.

## AI 지적이 부정확 (코드검증)

- 대시보드 상단에 **NATS와 PLC가 각각 초록색으로 표시된다**는 제안은 부정확하다. 현재 상단에는 PLC 표시와 Agent 온라인 수가 있으며, 별도 NATS 상태등은 없다.
- START 전 **셔터 닫힘·카메라 Ready 표시를 확인**한다는 제안은 현재 대시보드 기능으로 확인되지 않는다.
- Agent 실행 파일을 `AgentUI.exe`로만 특정하면 부정확하다. 저장소에는 콘솔 Agent와 WPF AgentUI가 모두 있다.
- “Master를 먼저 닫으면 Agent 연결 오류 로그가 발생하므로 반드시 Agent PC부터 종료”한다는 근거는 코드에 없다.
- 종료 순서 위반 시 데이터 손실·공정 이상이 발생한다고 단정할 코드 근거도 없다.
- 레시피 완료 시 별도 안내 메시지가 표시된다는 표현은 부정확하다. 현재 구현은 상태 문자열을 `완료`로 변경한다.

## 보류 (설비 안전/도메인 확인 필요)

- PLC·카메라 장비 전원 점검, E-Stop 해제 확인의 현장 절차와 책임 범위.
- 알람·통신 끊김 발생 시 운전 지속 금지, 관리자 보고 및 재시작 기준.
- STOP과 설비 비상정지의 사용 조건 및 안전한 중단 완료 판단.
- Agent PC와 Master PC의 필수 종료 순서.
- 프로그램 강제 종료 금지와 그에 따른 실제 설비·데이터 영향.
