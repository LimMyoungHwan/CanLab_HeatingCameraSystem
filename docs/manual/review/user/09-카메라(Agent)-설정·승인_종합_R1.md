1. [도입부] 문제: Agent와 카메라의 관계가 불명확함 -> 제안: “Agent는 카메라 PC에서 실행되며, 하나의 Agent 설정에 여러 카메라 항목을 추가·삭제할 수 있다.”라고 명시한다. (`AgentSettingsViewModel.Cameras`, `AddCamera`, `RemoveCamera`; codex)

2. [에이전트 원격 설정] 문제: 실제 조작 순서가 없음 -> 제안: “온라인 Agent 선택 → [조회] → 값 확인·수정 → [설정 전송] → 화면 하단 성공/실패 메시지 확인” 순서로 작성한다. 조회 전에는 입력 폼이 숨겨지고 안내 문구만 표시된다. (`LoadAsync`, `ApplyAsync`, `IsLoaded`, ACK 상태 메시지; agy·claude·codex)

3. [버튼명] 문제: 기능명이 일반 문장처럼 보여 조작 요소와 구분되지 않음 -> 제안: 실제 UI 명칭인 `[조회]`, `[설정 전송]`, `[승인]`, `[거부]`, `[이름 저장]`, `[시리얼 전송]`, `[로그 가져오기]`로 통일한다. (각 XAML Command 바인딩; agy)

4. [하트비트] 문제: 운전자에게 생소한 용어임 -> 제안: “하트비트 주기(Agent 상태 보고 간격, 초)”로 설명한다. (`HeartbeatSeconds`, 하트비트 타이머; claude)

5. [카메라 목록] 문제: 무엇을 편집하는지 불명확함 -> 제안: Agent ID, OpenCV 인덱스, 별칭, 장치명, 시리얼 COM을 편집하며 `[카메라 추가]`와 `[삭제]`를 사용할 수 있다고 명시한다. (`AgentCameraRow`, AgentSettingsView.xaml; claude)

6. [설정 적용 시점] 문제: 전송 후 즉시 적용되는지 설명이 없음 -> 제안: “전송된 설정은 저장되며 AgentUI를 재시작한 뒤 적용된다. 성공 시 ‘저장됨. AgentUI 재시작 후 적용됩니다.’가 표시된다.”라고 명시한다. (`CameraNatsConnector.ApplyConfigAsync`; codex)

7. [전송 결과 확인] 문제: 설정 전송 성공 여부 확인 방법이 없음 -> 제안: 화면 하단 ACK 메시지를 확인하고, 응답이 없으면 Agent가 온라인 목록에 있는지와 Master·Agent의 NATS 연결 상태를 확인하도록 안내한다. 설정 조회·전송 자체에는 별도 시간 초과 처리가 없다. (`EnsureConfigSubscriptions`, `StatusMessage`; claude·codex)

8. [디바이스 관리] 문제: 기능의 대상과 사용 조건이 구분되지 않음 -> 제안: 미승인 장치를 선택한 경우에만 `[승인]`이 활성화되고, `[시리얼 전송]`은 승인된 장치에서만 활성화된다고 명시한다. `[거부]`, `[이름 저장]`, `[로그 가져오기]`는 장치 선택이 필요하다. (`HasPendingSelection`, `HasApprovedSelection`, `HasSelection`; codex)

9. [이름 저장] 문제: 저장 대상이 불명확함 -> 제안: 선택한 카메라의 Alias(별칭)를 AgentManager로 전송하고 Master의 카메라 장치 저장소에도 갱신한다고 설명한다. (`RenameAsync`; claude)

10. [로그 가져오기] 문제: 그림 23 설명에서 누락됨 -> 제안: 그림 23 캡처 대상에 `[로그 가져오기]` 버튼과 수신 로그 표시 영역을 포함한다. 로그 요청은 최대 5 MiB이며 30초 동안 응답이 없으면 시간 초과 메시지가 표시된다. (`GetLogsAsync`; claude)

11. [승인 절차] 문제: 발견과 승인의 구분이 모호함 -> 제안: “인벤토리는 자동 수신되지만 승인은 운전자가 미승인 장치를 선택하여 `[승인]`을 눌러 요청한다.”라고 명시한다. (`SubscribeCameraInventoryAsync`, `MergeInventory`, `ApproveAsync`; codex)

12. [그림 22·23] 문제: 조작 목적을 보여주는 상태가 부족함 -> 제안: 그림 22는 조회 완료 후 설정값과 카메라 목록이 표시된 상태, 그림 23은 미승인 장치가 선택되어 `[승인]` 버튼과 전체 작업 버튼이 보이는 상태로 캡처한다. (agy·claude·codex)

- codex가 기존 문구를 “자동으로 승인한다”는 의미로 해석할 수 있다고 지적했으나, 현재 코드는 자동 승인을 수행하지 않는다. 카메라 인벤토리 수신·목록 갱신은 자동이지만 승인은 `[승인]` 클릭으로 `ManagerCommandOp.Approve`를 전송하는 수동 절차다.
- codex가 “미승인 상태이면 촬영되지 않는다”는 후속 문구를 제안했으나, Master·Core·Protocols 코드만으로는 승인 상태가 모든 촬영 명령을 차단한다고 단정할 수 없다. 매뉴얼에는 승인 상태 확인과 승인 요청 절차까지만 기술하고 촬영 차단을 보장하는 표현은 사용하지 않는다.
